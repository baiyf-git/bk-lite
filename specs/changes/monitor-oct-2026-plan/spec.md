## 0. 月度主题（说人话）

**可观测总主题：** 【可观测：告警策略补相对计算 + 配完能验】

**Monitor 主题：** 【可观测·监控：策略能配 P95/环比，配完能试跑】

一句话：腰部客户在策略页用表单配「延迟 P95 超线 / 比上一窗多了多少 / 比 1 小时前同窗或 24 小时前同窗高多少」，保存前点试跑，当场看见会不会响。运营侧的维护窗、静默、抑制、通知编排继续只在告警中心。

## 1. 背景与问题

腰部私有化客户配监控告警，几乎只会写「当前值 vs 固定阈值」，例如 CPU 5 分钟均值 > 90%。业务一波动就误报或漏报：早高峰、发布窗口、日常潮汐都会被当成故障。

客户真正要说的是三句人话：

1. **看分布，不看均值。** 「接口延迟 P95 > 200ms」，不是「平均延迟 > 200ms」。
2. **看相对变化，不看绝对水位。** 「比刚才多了 200 个错误」或「比 1 小时前 / 24 小时前同窗高 50%」。
3. **配完先验，不敢干等扫描。** 相对计算配错的代价是静默误报；私有化现场没有人帮他们盯一夜。

仓库现状对不上这三句话：

- 策略页窗口算法只有 avg / max / min / sum / count / last，没有百分位。
- 没有变化量、没有环比。引擎侧 MetricsQL 能算同类函数，表单没开放。
- 策略页已有指标曲线「预览」，没有「这套条件现在会不会响」的试跑。
- 恢复只能「连续 N 个周期不再满足同一条触发阈值」，阈值附近会振铃。
- 无数据检测窗和恢复窗在模型上已经分开，前端保存写成同一个值。

Zabbix 用 Trigger 表达式能配 `percentile`、环比、同比、基线、`timeleft`。我们不把客户再送进表达式课，也**不对外说「对齐 Zabbix」**。十月只开放一张会切换量纲的表单，而且必须能当场试跑。完整方式清单按五档记在覆盖地图，档位才是承诺。

**问题陈述：** Monitor 策略页只有绝对值比较，也没有配完试跑；腰部客户无法用表单表达相对变化和分布类告警，更不敢把半成品策略开到生产上。

## 2. 目标客群与对比口径

### 2.1 目标客群

腰部客户、私有化交付。配置人通常是现场运维或交付工程师，不是 PromQL / Zabbix 表达式专家。他们要的是：

- 表单枚举，不手写查询语言。
- 配完立刻知道会不会响，不用等下一个扫描周期。
- 和 APM / Log 用同一套词培训，不要三个 App 三套黑话。
- 维护窗口、值班静默、升级分派有地方管——那个地方是告警中心，不是策略页再造一套。

### 2.2 对比口径

对外只比 **Monitor 判定 + 告警中心运营**，不是 Monitor 单品对标 Zabbix / 夜莺 / Datadog Infra 全家桶。售前禁止说「告警计算对齐 Zabbix」。

| 谁做 | 做什么 | 不做什么 |
|---|---|---|
| Monitor | 算出可比值、比阈值、产生域内告警；配策略时用同一套引擎试跑 | 不维护窗、不静默、不级别抑制、不通知编排、不升级分派 |
| 告警中心 | 收监控告警副本后做屏蔽、维护窗、分派、升级、事故、降噪 | 不代替 Monitor 算 P95 / 变化量 / 环比，不改 Monitor 的触发事实 |

售前话术只许说一句：**Monitor 负责判定和先验，告警中心负责运营。**  
十月验收不写「维护期不响」——那是告警中心屏蔽 / 维护窗的验收。  
试跑只回答「按当前条件，这一刻这些实例会不会触发」，不管告警中心后来是否压住通知。

覆盖对齐的是腰部常用比较方式，不是 Zabbix 触发器函数目录。十月施工只取覆盖地图里的 **必做**；建议做可排、落后必做一档。

## 3. 证据分层

### 仓库事实

- 窗口算法无分位：`WINDOW_AGGREGATION_ALGORITHMS` 与策略页 `useMethodList` 只有 avg / max / min / sum / count / last。
- 现有扫描链是 `query_condition → 窗口聚合 → VM query_range → threshold + trigger_count / recovery`。相对计算可以插在「窗口聚合之后、阈值比较之前」，不必新扫描架构。
- 恢复只有连续周期、同一阈值：`MonitorPolicy.recovery_condition`，`AlertDetector.recover_threshold_alerts`。
- 无数据双字段已被前端写死成同一个：策略详情保存时 `no_data_recovery_period = no_data_period`；表单只露一个检测时长。后端模型已经分开。
- 预览已有、试跑没有：`previewMonitorPolicy` / `metricPreview.tsx` 画曲线；没有「会不会响」入口，也不会走完整判定。
- 分工：Monitor 扫描产生领域告警并投影告警中心；屏蔽 / 分派 / 升级在告警中心。见 `CONTEXT.md`「领域告警 / 告警中心事件」、`docs/design-docs/monitor-module-architecture-analysis.md`、`docs/design/product-decisions/domain-alert-handlers.md`。
- `PolicyInstanceBaseline` 是无数据库存，只服务无数据检测，不能拿来做统计基线。

### 已确认产品决定

- 十月 Monitor 只补策略判定：相对计算 + 配完能验。
- 定稿 4 条，见第 4 节。1～3 必须交付；4 为建议做，与试跑抢工时先砍 4。
- 百分位只放告警条件一个入口；定义指标不再并排放 P90 / P95 / P99。十月百分位是评估窗内样本分位，不是直方图 `histogram_quantile`。
- 变化量 = 上一等长窗；短环比 = 当前评估窗整体平移 **1h / 24h**。界面写「1 小时前同窗 / 24 小时前同窗」，**不写「昨天」**。不做环比 5m（策略周期常为 5m 时，环比 5m ≡ 变化量）。
- 对照缺失 = 本轮不触发，不当 0。
- 试跑：未保存草稿即可；复用扫描引擎；不落告警、事件、快照、通知。结果含当前值、对照值、缺对照原因、本轮是否命中。连续 N 次才告时写明「本轮计一次命中，未达连续次数则现网不会建告警」。试跑评当前窗，不是历史回放。
- 滞回最多一条独立恢复阈值；未做时恢复线 = 触发线，仍靠连续 N 次。收入覆盖地图为建议做。
- 覆盖地图列出全部计算方式；档位（保持 / 必做 / 建议做 / 可后置 / 不建议）才是承诺。工时只决定哪一档先做，不把「不建议」从需求里删掉。
- 抑制 / 维护窗 / 静默 / 升级 / 通知编排只归告警中心。
- 三域只对齐用词，不对齐实现，不抽公共扫描库。
- 探针安装、覆盖一览、`push_targets` 不进 Monitor 十月，由节点管理承接。

### 当前假设

- 现有四则公式的结果序列可以套本月 `calc_mode`；不扩展公式语言。
- VM 留存能支撑 1h / 24h 对照。撑不住时保存 / 预览 / 试跑说明原因，不静默当 0。

### 待确认（不挡排期）

- `calc_mode` 附属字段落独立列还是 `calc_config` JSON：实现时二选一，须写入策略模板。
- 公式结果是否同期套变化量 / 环比。编译过复杂则公式十月只走固定阈值和百分位。
- 第 4 条恢复阈值的字段名：产品只要求「触发 / 恢复可以是两个值」，不锁列名。

### 4.1 百分位（P90/P95/P99），只放告警条件一个入口

**优先级：** 必须（P0）

**背景：**  
策略页窗口算法没有 `quantile_over_time`。腰部客户要配「延迟 P95 > 200ms」，只能拿均值硬套，或不会写的 PromQL。APM 已有 P95 指标类型；Monitor 是窗口分位，不是追踪分位，也不是直方图 bucket 分位。定义指标如果再放一套 P95，配置人会对着两个入口猜该改哪一个。

**要做什么：**  
告警条件增加「计算方式」，新建默认「固定阈值」。选「百分位」后只出现 P90 / P95 / P99，阈值仍写绝对值。定义指标继续只负责「取哪条序列、窗口怎么聚合」，不要并排再放 P90 / P95 / P99。

**不做什么：**  
任意分位滑条；定义指标里第二套百分位汇聚；手写 `quantile_over_time`；把 APM 的 `metric_type=p95` 搬进 Monitor；十月做直方图 `histogram_quantile`（覆盖地图：可后置）。

**实现要点：**

- 落 `calc_mode`。缺省 / 存量无字段 = `absolute`，扫描行为与改前一致。
- `percentile` 在窗口聚合之后编译分位序列；预览、扫描、试跑共用同一编译。
- 非法分位在保存期拒绝，不拖到扫描失败。
- 现有四则公式的结果序列可以套百分位；不扩展公式语言。
- 阈值量纲不变（仍是绝对值），先立计算方式选择器和存量兼容。

**验收标准：**

- 新建策略默认「固定阈值」；旧策略不改保存则扫描结果与现在一致。
- 保存 P95 策略后，扫描用分位序列比阈值，不是均值。
- 定义指标汇聚列表仍无 P90 / P95 / P99。
- 用户不用写 PromQL / Zabbix 表达式。
- 非法分位（如 P80、0.8 自由值）保存被拒绝。

**依赖：**  
无上游产品依赖。为第 2、3 条立 `calc_mode` 骨架。不依赖告警中心、节点管理。

---

### 4.2 变化量（上一窗）+ 短环比（1h/24h 同窗；缺对照不误报）

**优先级：** 必须（P0）

**背景：**  
绝对值会把早高峰、发布窗口当成故障。客户要的是「比刚才多了多少 / 比 1 小时前、24 小时前同窗高多少」。#17 写的 1d / 7d 偏长周期，和基础设施毛刺、以及 APM / Log 的短对照都不贴；草案里的环比 5m 又会和「上一窗」撞车。把 24h 说成「昨天」会绑自然日和时区，产品已否决。

**要做什么：**

- **变化量** = 相对上一等长汇聚窗，阈值用 Δ 或 %。
- **短环比** = 当前评估窗整体平移 1 小时或 24 小时，阈值用涨跌幅 % 或倍数。界面文案：「1 小时前同窗」「24 小时前同窗」。
- 上一窗或对照窗写不出来、失败、尚未形成：本轮不触发，不当 0。

**不做什么：**  
环比 5m、7d、30d；日历日「昨天」；同比；统计基线；容量预测；补零当对照；让用户手写第二条 PromQL 表示对照窗。

**实现要点：**

- 在窗口聚合之后、阈值比较之前做双查询或 `offset`。
- `change` 与 `mom` 保存值必须不同，表单文案也必须不同。
- 预览同时画出当前值与对照值，阈值线按变换后量纲。
- `1h` / `24h` 超出 VM 留存时，保存 / 预览 / 试跑说明原因，不静默当 0。
- 分组策略按组对齐对照窗；对不上的组按「缺对照」处理。
- 十月只做这一套短对照骨架；覆盖地图里的同比 / 基线以后复用它，本月不开发。

**验收标准：**

- 两种模式可保存、预览、扫描；阈值单位随模式切换（Δ / % / 倍数）。
- 本窗 120、上一窗 80，变化量变换后值为 40（或按所选 % 计算）；上一窗缺失则本轮不建告警、不发通知。
- 环比对照 1h 或 24h 缺失：本轮不触发，试跑写明「对照缺失」，不会显示成「下降 100%」。
- 表单不出现「环比 5m」，不出现「昨天同时段」。
- 用户不能手写对照查询。

**依赖：**  
第 1 条的 `calc_mode` 与存量 `absolute` 兼容先落地。不依赖告警中心。告警中心继续只收触发后的副本。

### 4.3 策略条件试跑（复用扫描引擎，不落告警/不通知）——必须

**优先级：** 必须（P0）。主题里的「能验」。不许排到第 3 周末再挤。

**背景：**  
现网只有指标曲线预览，没有「这套条件现在会不会响」。相对计算上线后，对照缺失、量纲切换更容易配错。腰部私有化现场配完不敢开，只能干等扫描。没有试跑，第 1、2 条在真实环境不可交付。

**要做什么：**  
策略页（含未保存草稿）在授权范围内选实例，点「试跑」，看到每个实例：会触发 / 会恢复 / 无数据 / 对照缺失 / 样本不足，以及用于比较的当前值、对照值、阈值。连续 N 次策略须区分本轮命中与现网会不会建单。

**不做什么：**  
试跑写入 `MonitorAlert` / `MonitorEvent` / 快照；试跑发本域通知或投告警中心；按告警中心屏蔽 / 维护窗预演「会不会通知」；把预览和试跑合成一个按钮；前端自己算 P95 / 变化量 / 环比来决定是否触发；做成历史回放播放器（「过去 24h 会告几次」）。

**实现要点：**

- 复用 Monitor 扫描的查询编译 + 判定（`AlertDetector` 同类逻辑），包一层只读试跑。
- 不写告警、事件、快照，不发通知，不推告警中心。
- 权限与策略可见实例一致，fail-closed：越权实例不可选、不可出数。
- 曲线预览仍叫「预览」，本条叫「试跑」，两个入口、两句人话。
- 试跑失败只留在策略页，不产生告警噪声。
- 连续 N 次：结论文案固定为「本轮计一次命中，未达连续次数则现网不会建告警」（未达时不显示成会建告警）。

**验收标准：**

- 同一套 P95 / 变化量 / 环比条件，试跑结论与下一次真实扫描一致（同一时刻、同一实例）。
- 试跑后告警列表、本域通知、告警中心均无新记录。
- 缺对照、无数据、样本不足、查询失败时，试跑明确「不触发 + 原因」，不会显示成触发。
- 越权实例不可选、接口也出不了数。
- 前端不得用本窗数字自己变换后判定。
- 策略要求连续 3 次才告时，单次试跑命中不得展示成「现网会建告警」。

**依赖：**  
第 1、2 条的变换逻辑先可复用；排在相对计算之后，才能验变换后的值。与告警中心无功能依赖；试跑结果不考虑屏蔽 / 维护窗。不依赖节点管理。

### 4.4 滞回恢复阈值 + 无数据检测/恢复窗拆开——建议做；与试跑抢工时先砍

**优先级：** 建议做（P1）。同迭代可排；与第 3 条抢工时则整条不做。覆盖地图档位：建议做。

**背景：**  
恢复今天是「连续 N 个周期不再满足同一条触发阈值」。CPU 在 79～81 抖动会振铃。无数据：模型已有 `no_data_period` 与 `no_data_recovery_period`，前端保存写成同一个值，恢复窗配不了更短。这两件事都是域内告警状态何时翻回，不是告警中心静默。

**要做什么：**

- 触发与恢复可以是两个阈值（如触发 >80、恢复 <70）；未填恢复阈值时行为与现在相同。
- 无数据表单拆成「检测窗」「恢复窗」，允许恢复窗更短，并分别保存、分别扫描。

**不做什么：**  
把滞回做成维护窗或静默；改 `PolicyInstanceBaseline` 的无数据库存语义；学 Zabbix 独立恢复表达式；只上其中一个半套（抢工时时整条砍，不拆一半）。

**实现要点：**

- 恢复比较走变换后的值；连续周期语义保留。
- 无数据只改表单绑定和保存，让已经分开的两个字段真能配出两个值。
- 不填恢复阈值 = 继续用触发阈值做「不再满足则恢复」，兼容存量。

**验收标准：**

- 触发 >80、恢复 <70：越过 80 触发；掉到 70～80 保持活跃；低于 70 才恢复。
- 不填恢复阈值时，打开、保存、扫描与改前一致。
- 无数据检测 10m、恢复 2m 可分别保存，并按各自窗口扫描。
- 本条若与试跑抢工时，整条降级，发布说明写「本迭代不做滞回 / 双窗」。

**依赖：**  
无数据双窗不依赖第 1～3 条。滞回若作用在百分位 / 环比策略上，恢复比较必须走变换后的值，因此实现上宜跟在第 1、2 条之后。不依赖告警中心。与第 3 条争全栈时间时，砍本条、保试跑。

## 5. 三周排期与可砍顺序

约 1 组全栈、国庆后 3 周。能做完的是「计算方式表单 + 一条变换引擎 + 一个只读试跑」。第 4 条实现面小于前三条，但不是主题，允许整条滑出。

| 周次 | 交付 | 砍闸 |
|---|---|---|
| W1 | `calc_mode` 缺省 `absolute`；百分位 P90/P95/P99 只出现在告警条件；存量兼容；预览量纲跟上 | 不做任意分位；定义指标不放 P95 |
| W1～W2 | 变化量（上一窗）+ 短环比（1h/24h 同窗）；双查询 / offset；缺对照不触发；预览画当前 vs 对照 | 不做环比 5m、7d、「昨天」、同比、基线 |
| W2～W3 | 试跑 API + 策略页入口；复用扫描编译与判定；不落告警、不通知；连续 N 次文案 | 试跑与扫描结论不一致则停第 4 条，先收口引擎 |
| W3 | 若 1～3 已验收：滞回恢复阈值 + 无数据双窗拆开 | 与试跑抢工时则整条不做 |

并行约束：

- 第 2 条不能先于第 1 条的 `calc_mode` 骨架。
- 第 3 条不能等第 4 条，也不能为第 4 条让路。
- 第 4 条不能和第 3 条抢最后几天。

**可砍顺序（按这个用，不要同时砍主保的两头）：**

1. 先砍第 4 条整条（滞回 + 无数据双窗一起砍，不拆一半）。
2. 不砍第 1 条的「一个入口」、不砍第 2 条的「缺对照不误报」、不砍第 3 条。没有这三条，相对计算不能上生产。
3. 任何情况下都不把同比、基线、容量预测、维护窗、静默、抑制、通知编排、表达式框加进十月。

3 周保「相对计算 + 能验」。做成半套相对计算、试跑落空，视为十月失败。

## 6. 与 APM / Log / 节点管理的边界与共用语言

三域十月都补「计算方式」，**只对齐用词，不对齐实现，不抽公共扫描库**。  
节点管理十月主保「装得上、看得见、接得上」；**探针安装不进 Monitor 十月清单**。  
四域锁定清单以 [overview.md](../oct-2026-plan/overview.md) 为准。

### 6.1 共用语言（变化量 = 上一窗，环比 = 1h/24h 同窗，缺对照不误报，试跑不落告警）

| 用户看见的词 | 三域同一句话 | Monitor 十月 | APM | Log | 节点管理 |
|---|---|---|---|---|---|
| 计算方式 | 窗口数字怎么变成拿去比阈值的值 | 要上 | 要上，按 RED 裁 | 要上，按 LogsQL 计数裁 | 不上。节点不算阈值 |
| 固定阈值 | 当前窗绝对值比固定数 | 存量缺省 | 存量缺省 | 聚合缺省 | 无 |
| 百分位 | 窗口分布的 P90/P95/P99 | **主路径** | 已是指标类型，不要再做 `calc_mode=percentile` | 不做十月 Monitor 的事 | 无 |
| 变化量 | 相对**上一等长窗**的 Δ 或 % | **主路径** | 主路径之一 | 主路径（速率 / 突增） | 无 |
| 环比 | 相对用户选的对照窗，阈值是 % 或倍数 | 对照 **1h/24h 同窗** | 对照 1h/24h 同窗 | Log 十月不做 1h/24h 档，只做上一窗 | 无 |
| 对照缺失不误报 | 对照窗没数据，本轮不触发，不当 0 | 必须 | 必须 | 必须 | 无 |
| 预览 | 看变换后的曲线 / 对照 | 已有曲线预览，要跟计算方式走 | 已有 | 已有 | 无 |
| 试跑 | 选对象，问「现在会不会响」，不落单 | **本迭代必须做** | 必须；用本域引擎 | 必须（Log 称试算）；用本域引擎 | 无。节点侧「装完能验」验的是心跳 / 采集器，不是告警条件 |
| 维护窗 / 静默 / 抑制 | 运营侧降噪 | **禁止进 Monitor** | 禁止进 APM | 禁止进 Log | 禁止进节点管理 |

运营词（静默、维护窗、抑制、升级、编排）四个 App 都不要在本域策略页或安装页新造一份。

### 6.2 产品边界

| 对象 | Monitor 十月做 | 交给别人 |
|---|---|---|
| 策略判定（P95 / 变化量 / 环比） | 做 | APM / Log 各算各的序列，不复用 Monitor 扫描 |
| 策略试跑 | 做，只读 | 告警中心不做试跑；APM / Log 必须用本域引擎 |
| 域内恢复 / 无数据窗 | 第 4 条，建议做 | 不是告警中心静默 |
| 维护窗 / 静默 / 级别抑制 / 通知编排 | 不做 | 告警中心 |
| 域内处理人 / 认领 / 分派 | 本迭代不重做 | 已有轻量闭环，见领域告警处理人决策 |
| 探针安装 / 覆盖一览 / 节点 ↔ 三域 ID | 不做 | 节点管理十月 |
| 指标写入 / 采集器托管 | 不做 | 节点管理 + Stargazer / Collector |

Monitor 继续是控制面和查询面，不是指标写入面。十月不碰采集插件、实例接入、仪表盘。

## 7. 明确禁止项

下列能力整月不准进 Monitor 十月**施工范围**，也不许写进本迭代验收。覆盖地图仍保留条目，避免被当成遗漏。

- **告警运营：** 维护窗、静默、屏蔽、级别抑制、通知编排、升级、分派重做、告警中心侧试跑。
- **表达式：** Zabbix Trigger 编辑器、自由 PromQL、任意分位滑条。
- **覆盖地图可后置 / 不建议：** 同比、统计基线、容量预测、直方图分位、STL、公式函数库、ML 异常检测。
- **结构债：** 三域公共 `calc_mode` 扫描库；试跑落库或发通知；把 `PolicyInstanceBaseline` 拿来做统计基线。
- **入口重复：** 定义指标里再放一套 P90 / P95 / P99；环比 5m（与变化量撞车）；界面写「昨天同时段」。
- **节点侧工作：** 探针安装、覆盖一览、`push_targets`、Sidecar 心跳验收。
- **本迭代不重做：** 域内处理人 / 认领 / 分派、通知渠道、策略公式编辑器本身。
- **对外话术：** 「对齐 Zabbix」。

十月结束时，对外可讲的仍是一句人话：策略能配 P95 和 1h/24h 同窗环比，配完能试跑。运营降噪继续在告警中心。

## 9. 给评审会的短结论

十月 Monitor 只做一件事：策略能配 P95 / 1h/24h 同窗环比，配完能试跑。

- 百分位只留告警条件一个入口（点值序列分位，不是直方图）。
- 变化量 = 上一窗，短环比 = 1h / 24h 同窗，不写「昨天」；缺对照不误报。
- 试跑必须交付，复用扫描引擎，不落告警、不通知；连续 N 次须说明本轮命中 ≠ 现网建单。
- 滞回 + 无数据双窗并成第 4 条，建议做；和试跑抢工时先砍。
- 全部计算方式记在覆盖地图，档位才是承诺。不对外说对齐 Zabbix。
- 维护窗 / 静默 / 级别抑制 / 通知编排继续只进告警中心。
- 3 周保「相对计算 + 能验」。

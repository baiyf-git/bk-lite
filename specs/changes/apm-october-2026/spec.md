## 0. 共享词汇（全文只用这一套）

| 词 | 含义 | 不要说成 |
|---|---|---|
| **变化量 `change`** | 当前窗口相对**上一相邻窗口**的 Δ 或涨跌幅 % | 环比、同比、基线、异常 |
| **短环比 `mom`** | 当前窗口相对枚举对照：上一窗 / **1 小时** / **1 天**；比较方法为涨跌幅 % 或倍数 | Monitor 默认的 7 天环比、30 天同比 |
| **试算** | 用扫描同一套判定，回答「按这套规则现在会不会告」 | 指标预览、告警回放、屏蔽预演 |
| **对照缺失** | 对照窗还没形成、查不到或没有可比样本 | 无数据、吞吐为 0、查询失败 |
| **无数据** | 当前窗口 VictoriaTraces 没有可聚合样本 | 对照缺失、取数失败 |
| **试算永不落告警** | 试算不写 Alert / Event / 快照，不发通知，不抄送告警中心 | 保存即扫描、试运行建单 |

计算方式语言与 Monitor / Log 同名（`absolute` / `change` / `mom`），各自作用在本域序列上，**不共用查询引擎**。

## 1. 月度主题（说人话）

### 【可观测：告警策略补相对计算 + 配完能验】

十月可观测总主题：Monitor / APM / Log 都让腰部客户用表单表达「比刚才 / 比上一窗」，并且保存前能看见会不会告。三域共用计算方式语言，各自算自己的数。屏蔽、维护窗、降噪、升级仍在告警中心。

- **监控中心 / 日志中心：** 各走自己的十月规划，本文不改。
- **APM：** 见下一句。

### 【可观测·APM：相对变化能配、配完能验；看不见的调用不漏】

十月结束时，售前只需要讲两句话：

1. 客户能在策略页用表单配「这 5 分钟比上一窗差多少 / 比 1 小时前高多少」，保存前能看见会不会告。
2. 跨组织调用链只露出本组织看得见的 Span；看不见的服务名、耗时、属性不会跟着漏出来。

相对计算是主卖点。Trace 隔离是必须同时收口的信任债，单独成条，不写进主题中心词。  
最低吞吐门槛是「有余量再做」的单模板；探索分页默认可砍。

## 2. 背景与竞品依据

### 2.1 为什么是这一个月

腰部客户今天配 APM 告警几乎只会写「5 分钟错误率 > 5%」。大促或夜间流量一变，不是误报就是漏报。策略页右侧已有「指标预览」，只回答「现在是多少」，不回答「按这个规则现在会不会告」。相对计算一旦开放，没有试算就不敢上生产。

同时，探索列表已经按组织丢掉不可见行，详情却只要调用链里有一条本组织 Span，就把整条 Trace（含其他组织的服务名、耗时、属性）一起返回。这是越权，不是体验优化。跨组织客户在看相对计算之前，必须先能相信调用链不会漏。

### 2.2 仓库事实

- `ApmPolicy.metric_type` 只有 `error_rate / p95 / p99 / throughput / no_traffic`。窗口内 `aggregation`（avg / max / min / last）得到一个值，再比 `thresholds[]`。已有 `trigger_after` / `recover_after`、可选 `no_data_after`。没有 `calc_mode`，没有对照窗。见 `server/apps/apm/models/control_plane.py`。
- 扫描链路是 `service_red → 窗口聚合 → 阈值比较 → 连续次数`。`test_query` 只算当前窗绝对值，并返回 `breached`。见 `server/apps/apm/services/policies.py`。
- 策略编辑器四段：基本信息、指标定义、告警条件、通知配置；右侧「指标预览」走 `previewPolicy` → `test_query`。见 `web/src/app/apm/events/policies/policy-editor.tsx`。
- 探索列表用 `collect_visible_page` 先过滤再算游标。详情 `can_view_detail` 是「任一 Span 可见即整链放行」，`retrieve` 原样返回全部 Span。见 `server/apps/apm/services/trace_access.py`、`server/apps/apm/views/traces.py`。
- 敏感属性脱敏已在。查询窗最长 35 天。禁止任意查询语言。见 `specs/capabilities/apm-product.md`、`apm-alerting.md`。
- APM 拥有判定与域内生命周期；事件副本单向抄送告警中心，告警中心不得回写。见 `CONTEXT.md`「领域告警 / 告警中心事件」、`docs/design/product-decisions/domain-alert-handlers.md`。
- 探针安装由节点管理承接。APM 已按云区域解析区内 OTLP/HTTP `:4318`，探针制品走 APM 下载口，不走节点管理包上传。见 `docs/operations/apm-probe-artifact-release.md`。十月 APM **不把安装器写进本清单**；区内接入点与探针制品与节点管理共背，另册验收。

### 2.3 竞品怎么对照（只对照十月用得上的）

对照口径是 **APM 判定 + 告警中心运营**，不是拿 APM 单模块对标 Datadog 全家桶。

| 能力 | 我们现在 | Datadog APM | 阿里云 ARMS | SkyWalking | 十月怎么补 |
|---|---|---|---|---|---|
| 固定阈值 | 有，五类指标 | 有 | 有 | 有 | 保持；存量当 `absolute` |
| 变化量 / 短环比 | 无 | Change Alert | 环比 / 上小时 / 昨日 | MQE trend（表达式） | **做 `change` + 短 `mom`**。用户不写表达式 |
| 对照缺失 | — | 缺对照通常不硬算 | 可「补零」强行算出环比 | 视查询 | **缺对照 = 本轮不触发**。不学补零 |
| 配完会不会告 | 只有当前值预览 | Test monitor 一类 | 阈值对比图 | 弱 | **在现有预览上加试算结论**，复用扫描 |
| 低流量护栏 | 无 | Composite | 「错误率 AND 最低调用」 | MQE `&&` | **只做这一条模板**，不做通用 AND/OR |
| 组织 / 数据范围 | 列表后过滤；详情整链放行 | 限制 / 范围隔离 | 资源权限 | 多租户视部署 | **详情按 Span 裁剪** |
| 屏蔽 / 维护窗 / 级别抑制 | 告警中心已有 | Downtime | 告警管理屏蔽 | `silence-period` | **APM 不做** |
| 探索翻页 | 9 月已修一轮后过滤游标 | — | — | — | **默认可砍**；无复现用例不开工 |

缺口不是「没有 APM 告警」，而是「不能说相对变化、不能先验、跨组织详情会漏」。

### 2.4 证据分层

**已确认产品决定（产品讨论已锁，本文不再重开）：**

- 十月 APM 主卖点是相对计算能配、配完能验；Trace 隔离必须同期收口。
- `change` = 上一相邻窗；`mom` = 上一窗 / 1h / 1d。不做 7d / 同比 / 统计基线 / ML 异常。
- 对照缺失不误报，不当 0，不写成无数据。
- 试算复用扫描引擎，永不落告警、不发通知、不抄送、不预演告警中心屏蔽。
- 最低吞吐只做「错误率 / 时延 AND 吞吐 ≥ N」；不是通用条件构造器。无容量则整条移十一月。
- 探索分页默认砍。
- 屏蔽 / 维护窗 / 级别抑制归告警中心。探针安装归节点管理。
- 不抽三域公共 `calc_mode` 库；语言对齐即可。

**当前假设（不挡排期）：**

- 试算看「现在这套条件套在最近一个完整窗上会怎样」，不是回放历史每一次扫描。
- 连续次数若拿不到历史状态，试算只保证当前窗是否越线，并写清「仍须连续 N 次才会告」。
- 拓扑若仍按全链聚合不可见边，与详情裁剪一并改；不另开拓扑项目。

**待确认（不挡排期，默认按括号内走）：**

- `mom` 的「1 天」对照若 W2 留存或双查询吃紧，可先只留上一窗和 1 小时（见砍单顺序）。
- 最低吞吐门槛的单位沿用现有吞吐（req/s 量纲），不新造「调用次数」指标类型。

## 3. 与告警中心 / 节点管理边界

| 谁做 | 十月做什么 | 不做什么 |
|---|---|---|
| **APM** | 取出 RED 序列，按 `absolute` / `change` / `mom` 变换后再比阈值；试算同一套数；按 Span 裁剪跨组织 Trace | 不屏蔽、不设维护窗、不做级别抑制、不降噪、不升级、不把静默做成策略字段 |
| **告警中心** | 收 APM 事件副本后做屏蔽、维护窗、级别抑制、分派、升级、事故、降噪 | 不代替 APM 算变化量 / 环比，不回写 APM Alert / Event |
| **节点管理** | 探针装得上、状态看得见；与 APM 共背区内 OTLP 接入点和探针制品能下到机器 | 不算 P95 / 环比，不配 APM 策略，不裁 Trace |
| **Monitor / Log** | 各域自己的相对计算 + 试算（见各自十月规划） | 不复用 APM 扫描；APM 也不搬 MetricsQL / LogsQL |

对外只说一句：**APM 负责判定、证据和调用链可见范围；告警中心负责响不响的运营；节点管理负责探针对不对得上。**

十月验收不写「维护期不响」——那是告警中心屏蔽 / 维护窗的验收。  
试算只回答「按当前条件，这一窗会不会触发」，不管告警中心后来是否屏蔽通知。

SkyWalking `silence-period`、Datadog Downtime、SigNoz maintenance **不要**做成 APM 字段。APM 继续只用 `trigger_after` / `recover_after` 抗毛刺。

## 5. 需求拆条

### 5.1 跨组织 Trace 隔离：看得见的 Span 不得带出整条越权调用链

**优先级：** 必须  

**背景：**  
探索列表已经按组织丢掉不可见行，但打开详情时，`can_view_detail` 只要命中一条本组织 Span，就整链返回。跨组织调用会把组织 B 的服务名、耗时、属性带给组织 A。这是信任债，不是体验优化。

**用户价值：**  
跨组织客户敢把调用链给一线排障。看不见的服务不会出现在瀑布图、火焰图、列表或属性里；别人也不能靠猜 `trace_id` 枚举到这些数据。

**范围：**

| 做 | 不做 |
|---|---|
| 详情、瀑布图、火焰图、Span 列表、属性、计数只保留当前组织可见 Span | 靠前端藏节点 |
| 没有任何可见 Span 的 Trace 继续 404，与「不存在」不可区分 | 给不可见节点占位符、灰显服务名、或返回「被裁服务叫什么」 |
| 从可见 Span 点进详情，只看到可见片段；上游被裁时只提示「部分调用不可见」 | 为了拓扑好看补回不可见边的对端名称 |
| 列表、Span 探索、错误样本下钻走同一套可见性 | 重做探索产品、开放任意 QL |
| 拓扑若仍按全链聚合，只聚合可见边 | 另开拓扑项目或改推断下游规则 |
| 敏感属性脱敏不回退 | 改组织模型、改服务授权页 |

**验收标准：**

1. 组织 A 可见、组织 B 不可见的同一条跨服务 Trace：A 的详情里没有 B 的 Span、属性、服务名；`span_count` 只计可见。
2. 用 B 的 `trace_id` 直接打详情：404，与「不存在」不可区分。
3. 列表、Span 探索、错误样本下钻不能一个入口漏、另一个入口堵。
4. 可见片段的父子关系仍可读；被裁上游只出现「部分调用不可见」，文案不含被裁服务名。
5. 敏感属性脱敏不回退。
6. 不得为凑「看起来像完整调用链」而把不可见 Span 下发给前端。

**依赖：**  
只依赖现有组织授权与 `TraceAccessResolver`。不依赖第 2–4 条，不依赖告警中心。可与策略工作并行，但不要拖过第 1 周。

**建议实现要点（产品级）：**

- 详情授权从「有一条可见就整链放行」改为「按 Span 裁剪后再返回」。列表后过滤保持。
- 可见性判定留在服务端。前端只渲染已经裁过的数据。
- `span_count`、截断标记、拓扑边都按裁剪后的集合算，避免详情已裁、图上仍出现不可见服务。
- 不要引入「部分可见 Trace」的新资源类型；404 / 可见片段 / 「部分调用不可见」三态足够。

### 5.2 策略计算方式：变化量与短环比，对照缺失不误报

**优先级：** 必须  

**背景：**  
腰部客户现在只能写「当前窗口错误率 / P95 / 吞吐 vs 固定阈值」。扫描侧已经能从 VictoriaTraces 取出 RED 序列，表单没开放相对变换。Datadog 用 Change Alert，ARMS 用环比 / 上小时 / 昨日；我们用表单枚举，不让用户学表达式。原 #19 是本条需求来源，明细并入本节，不再单独成包。

**用户价值：**  
客户能说「这 5 分钟错误率比上一窗高 3 个百分点」「当前小时吞吐比 1 小时前高 50%」，而不必把阈值天天跟着流量改。夜间没有对照时，系统不把它当成「下降 100%」误报。

**范围：**

| 做 | 不做 |
|---|---|
| 告警条件增加计算方式：`absolute` / `change` / `mom` | `yoy`、统计基线、ML / Watchdog 异常、容量预测（`timeleft`） |
| `change`：相对上一相邻窗，Δ 或涨跌幅 % | 用户手写 `offset` 或第二条追踪查询 |
| `mom`：对照枚举为上一窗 / 1h / 1d；涨跌幅 % 或倍数 | Monitor 默认 7d、30d 同比 |
| 存量无 `calc_mode` 按 `absolute` 扫描，行为与改前一致 | 改默认值去「带偏」老策略 |
| `no_traffic` 只允许 `absolute`；相对计算保存期拒绝 | 给无流量套变化量 / 环比 |
| `trigger_after` / `recover_after` / 无数据在所有已发布模式下继续有效，比较对象改为变换后的值 | 把静默 / 维护窗做成 APM 字段 |
| 对照缺失 ≠ 无数据 ≠ 查询失败；缺对照本轮不触发 | 对照窗补零、把缺对照写成无数据告警 |
| P95 / P99 仍是 `metric_type` | 再做一套 `calc_mode=percentile` |
| 用户不写 PromQL / LogsQL / 公式 | 通用表达式编辑器 |

**计算方式明细（原 #19，已按十月裁剪）：**

表单原则：用户选枚举，不手写偏移。`calc_mode` 作用在已选 `metric_type` 序列上，不新增第三套指标类型。计算发生在 **窗口聚合之后、比阈值之前**。

| 批次 | 能力 | 用户怎么配 | 场景 | 关键行为 | 十月是否验收 |
|---|---|---|---|---|---|
| 已有 / 默认 | 固定阈值 `absolute` | 新建默认；阈值仍是绝对值 | 5 分钟错误率 > 5%；P95 > 200ms | 存量缺省即此 | **要。** 不改保存则扫描结果不变 |
| 已有 | 五类指标 | 指标里选错误率、P95、P99、吞吐或无流量 | RED 水位 | 枚举不变 | **要。** 现网五类仍可配、可预览、可扫描 |
| 已有 | 无流量 | 只走 `absolute` | 服务 / 端点突然没流量 | 禁止套 `change` / `mom` | **要。** 保存相对计算时拒绝 |
| 已有 | 连续触发 / 恢复 | `trigger_after` / `recover_after` | 抗毛刺 | 比较对象改为变换后的值；次数语义不变 | **要。** 相对模式下仍按连续次数 |
| 已有 | 无数据 | `no_data_after` | 当前窗无样本 | 查询失败不当成无数据；对照缺失走「不触发」 | **要。** 文案与对照缺失分开 |
| **P0** | 变化量 `change` | 计算方式 = 变化量；无长偏移 | 本 5 分钟错误率比上一窗高 3 个百分点；吞吐比上一窗多 200 req/s | `compare_method=delta\|percent`；上一窗缺失本轮不触发（不当 0）。与 `mom` 不共用「1d」语义——`change` 只看相邻窗 | **要** |
| **P0** | 短环比 `mom` | 计算方式 = 环比，对照选上一窗 / 1h / 1d | 当前小时错误率比上一小时高 50%；今日同时段吞吐比昨天高 1 倍 | `compare_offset` + `compare_method=percent\|ratio`；对照缺失不触发 | **要。** 1d 可按砍单顺序后置 |
| 后置 | 更灵活分位 / 场景化延迟 | P90 或「关键接口延迟」预填 | 登录 P90 > 300ms | 分位仍是取哪条序列，不是 `calc_mode` | **十月不验收** |
| 后置 | 同比 `yoy` / 基线 / ML 异常 | — | 大促同比、偏离近 7 个同期窗 | 复用对照模型，但不进本月表单 | **十月不验收** |

**字段落库（需求级，不是表结构强制）：**

- `calc_mode` 必有，缺省 `absolute`。
- 按模式使用 `compare_offset` / `compare_method`。独立列或 `calc_config` JSON 实现时二选一，须随 `ApmPolicy` 保存，编辑能回填。
- 快照与预览展示**变换后用于比较的值**。不改 Alert / Event / 快照生命周期语义。
- 非法组合（含 `no_traffic` + `change` / `mom`、相对模式缺比较方法）在 API 保存期拒绝，不拖到扫描失败。

**验收标准：**

1. 告警条件出现「计算方式」选择器；新建默认 `absolute`。切换后阈值量纲跟着变（绝对值 / Δ / % / 倍数）。
2. 存量无 `calc_mode` 的策略按 `absolute` 扫描，不改保存则结果与改前一致。
3. `change`：相邻 `metric_window` 的 Δ 或 %；预览画变换后的值，不是只画原始水位。
4. `mom`：对照只能选自上一窗 / 1h / 1d；阈值按 % 或倍数命中；预览能看出「现在 vs 对照窗」。
5. 对照窗或上一窗缺失：本轮不触发，不当 0，不写成无数据告警。
6. 用户不写 PromQL、LogsQL、公式。
7. `no_traffic` + 相对计算：保存拒绝。
8. 已有五类指标、多级阈值、处理人、通知、告警中心抄送不回归。
9. 未发布模式（`yoy` / `baseline` / `anomaly`）不出现在生产表单。

**依赖：**  
只依赖现有 `service_red` 与双窗查询。不依赖告警中心。不依赖第 1 条，但第 3 条依赖本条变换已存在。不抽三域公共库；枚举名跟 Monitor / Log 即可。

**建议实现要点（产品级）：**

- 选择器放在**告警条件**，不放指标定义。指标定义继续负责「哪条服务、哪个 `metric_type`、窗口怎么聚合」。
- 对照偏移用枚举，不暴露自由分钟数。
- 预览与扫描共用同一变换函数。页面只展示，不算第二套规则。
- 吞吐已是速率，不另开 `rate`。P95 / P99 不要再做成 Monitor 那种 `calc_mode=percentile` 主路径。
- 不要学 ARMS 对照补零。深夜无流量必须是「对照缺失 → 不触发」。

### 5.3 策略试算：当前值、对照值、会不会告（复用扫描引擎）

**优先级：** 必须  

**背景：**  
配完不能验，相对计算更不敢开。现有右侧预览只回答「现在是多少」，`test_query` 虽已返回绝对值是否越线，但没有对照值、没有变换后比较值、没有对照缺失 / 连续次数等不触发原因。这是第 2 条的验收面，不是新模块，也不新开试算页。

**用户价值：**  
策略配置人保存前就能看见：现在多少、对照多少、变换后多少、会不会告、不告是为什么。售前可以当场演示「配环比 → 看见会不会告」，而不必等到下一个扫描周期。

**范围：**

| 做 | 不做 |
|---|---|
| 在现有预览上增加试算结论 | 新开试算页、历史回放时间轴 |
| 展示当前窗值、对照窗值（若有）、变换后比较值、命中级别 | 前端用本窗数字自己算 Δ / % 来决定是否触发 |
| 不触发原因分为：未越线 / 对照缺失 / 窗口无数据 / 未达到连续触发次数 | 把查询失败装成无数据或对照缺失 |
| 未保存草稿可试算 | 试算写 Alert、Event、快照 |
| 只读：不发通知、不抄送告警中心 | 预演告警中心屏蔽 / 维护窗 / 升级结果 |

**验收标准：**

1. 同一组配置，试算「会触发」当且仅当扫描引擎用同一时刻判定也会触发。
2. `change` / `mom` 能同时看到现在 vs 对照；对照缺失时结论为不触发，原因可读。
3. 查询失败单独提示「取数失败」，不得装成无数据或对照缺失。
4. 未保存的草稿可试算；试算不写 Alert、不发通知、不抄送告警中心。
5. 试算不展示、不预测告警中心屏蔽 / 维护窗 / 升级结果。
6. 按钮 / 标题文案用「试算会不会告」，不和「指标预览」抢词。
7. 连续次数拿不到历史时，写清「当前窗口已满足阈值，仍须连续 N 次才会产生告警」；不得假装预知过去 N 个周期。

**依赖：**  
第 2 条的变换已存在。不要先做独立试算页。与告警中心无功能依赖。

**建议实现要点（产品级）：**

- 预览 API 必须走扫描同一套取数、对照窗、变换和阈值判断。发现双实现就停第 4 条，先收口。
- 连续次数可按「若这是第 1 次命中」说明；历史状态拿不到就明示，不要编造。
- 试算失败只留在策略页，不产生告警噪声。

### 5.4 最低流量门槛：错误率 / 时延告警可同时要求最低吞吐

**优先级：** 可砍（无容量则整条移十一月）  

**背景：**  
绝对错误率和相对变化在低流量下都容易误报（1/5 就是 20%）。ARMS 最佳实践是「错误率 AND 调用次数 ≥ N」。这是竞品多条件里腰部客户真正会配的那一条，不是通用 AND/OR。

**用户价值：**  
低峰或刚接入的服务不会因为「分母太小」半夜把值班人叫起来。配置人只多开一个开关、填一个吞吐下限。

**范围：**

| 做 | 不做 |
|---|---|
| 主指标为错误率、P95 或 P99 时，可选「同时满足最低吞吐」 | 通用 AND/OR、条件组、任意第三条指标 |
| 打开后主条件与最低吞吐 **同时满足** 才算命中 | OR、错误率 OR 时延、表达式拼接 |
| 主条件是 `change` / `mom` 时，门槛仍看 **当前窗口吞吐绝对值** | 对吞吐再套一层环比当门槛 |
| 试算同时展示两项是否满足 | 主指标为吞吐或无流量时仍露出该开关 |
| 通知 / 告警内容能看出「因未达最低吞吐未告」或「主条件 + 门槛同时命中」 | 用半成品表达式顶上本条 |

**验收标准（只有真做时才算）：**

1. 错误率 > 5% 且 5 分钟吞吐 < 门槛：不告。
2. 错误率 > 5% 且吞吐达标：告。
3. 主条件是 `change` / `mom` 时，门槛仍看当前窗口吞吐绝对值，不看吞吐的环比。
4. 主指标为吞吐或无流量时，不出现该开关。
5. 试算同时展示主条件与门槛是否满足。
6. 门槛单位沿用现有吞吐量纲，不新造「调用次数」指标类型。

**依赖：**  
第 2–3 条的判定出口稳定。否则门槛会和相对计算各算各的。不依赖告警中心。

**建议实现要点（产品级）：**

- 产品上这是主条件的**护栏**，不是第二条对等策略。
- 第 3 周末仍未开工，整条降级到十一月，**禁止**用半成品表达式或「先让用户填两个条件」顶上。
- 不要顺手做「错误率 OR 时延」。

**砍法：**  
W3 前两天仍未开工 → 整条移十一月。不要做成「开关在、扫描不算」。

### 5.5 探索后过滤分页正确性

**优先级：** 默认可砍  

**背景：**  
组织后过滤发生在存储分页之后，游标一旦跟存储页绑死，就会漏行、重复或提前结束。9 月已修一轮列表分页与 `collect_visible_page`；本条只收**可复现**的正确性，不重做探索。

**用户价值：**  
跨组织环境翻页时，看得见的调用链不会丢、不会重复、不会提前没下一页。价值低于前三条，不能和相对计算抢全栈带宽。

**范围：**

| 做 | 不做 |
|---|---|
| 只修调用链 / Span / 错误探索在「后过滤 + 翻页」下的漏行、重复、提前没下一页 | 重做探索、改默认 50 条、改 35 天查询窗 |
| 容量上限与「近窗样本 ≠ 窗内全量」口径保持 9 月结论 | 为凑满一页放宽组织过滤 |
| 先有失败用例再开做 | 无复现仍排期「顺便修一下」 |

**验收标准（只有真做时才算）：**

1. 构造「存储页大量不可见、可见行跨多页」时，连续翻页不丢可见行、不重复、结束时无下一页。
2. 不得为凑满一页放宽组织过滤。
3. 不得为了翻页把不可见行返回给前端再藏。

**依赖：**  
无产品依赖。与第 1 条可见性同一套过滤函数时，第 1 条改完后应用同一后过滤，不必单独立项。

**建议实现要点（产品级）：**

- 先用失败用例证明还在漏，再开做。测不过例则从十月正文拿掉，记入质量债。
- 8 次拉取上限若仍导致「可见行未满但还有下一存储页」，只在有复现时修，不扩成无限拉取。

## 6. 三周排期与砍单顺序

假设：国庆后约 3 周、**一个全栈小组**、并行 Monitor / Log 的 `calc_mode` 但不共用实现。略满，必须预留砍刀。

| 周次 | 保底交付 | 说明 |
|---|---|---|
| 第 1 周 | 第 1 条 Trace 隔离；第 2 条模型 + `change` 扫描骨架 | 信任债先收口，避免相对计算做完还不敢给跨组织客户看调用链 |
| 第 2 周 | 第 2 条 `mom` + 对照缺失；第 3 条试算结论上预览 | 这周结束必须能对外演示「配环比 → 看见会不会告」 |
| 第 3 周 | 第 2–3 条打磨与存量兼容；有余量再做第 4 条最低吞吐门槛 | 第 5 条默认不排期 |

**必须保住（砍到只剩这些也算十月成功）：**

1. Trace 详情不再越权。
2. `absolute` 兼容 + `change` + 短 `mom`，对照缺失不误报。
3. 试算能回答会不会告，且与扫描一致。试算永不落告警。

**有余量再做：** 第 4 条最低吞吐门槛（单模板）。

**容量不够先砍（顺序，按此用，不要各砍一半）：**

1. 第 5 条探索分页——默认砍。
2. 第 4 条最低吞吐门槛——整条移十一月，禁止改成通用 AND/OR 残骸。
3. `mom` 的「1 天」对照——只留上一窗和 1 小时，降低留存与双查询成本。
4. 试算里的连续次数解释——可先只给当前窗口是否越线，文案写清「连续次数以扫描为准」。

**不要用「各做一半」换看起来条目多。** 宁可十月只有隔离 + 变化量 + 试算闭环。

**并行约束：**

- 第 3 条依赖第 2 条的变换已存在；不要先做独立试算页。
- 第 4 条依赖第 2–3 条的判定出口稳定。
- 第 1 条与策略工作无产品依赖，可并行，但不要拖过第 1 周。
- 第 5 条不能和第 2–3 条抢最后几天。

## 7. 风险

| 风险 | 为什么会炸 | 产品处理 |
|---|---|---|
| 三周单全栈做 5 条，条条做薄 | 同时改策略模型、扫描、探索查询 | 保 1–3；第 4 条只做单模板；第 5 条默认砍 |
| 对照窗当 0 | 学 ARMS 补零，深夜无流量会被当成「下降 100%」 | **对照缺失 = 本轮不触发**，与无数据分开文案 |
| 试算和扫描两套逻辑 | 预览好看、夜间扫描不一致，售前当场翻车 | 试算必须走同一判定函数 |
| 多条件做成表达式 | 与「禁止任意 QL」冲突，十月收不住 | 只开放「主条件 + 最低吞吐」；来不及就整条不做 |
| 把静默抄进 APM | SkyWalking `silence-period` / Datadog Downtime 看起来像策略字段 | 运营去告警中心；APM 只用连续次数抗毛刺 |
| 详情「有一条可见就整链放行」没改干净 | 列表堵了、属性 / 拓扑 / 错误下钻仍漏 | 所有读 Trace 的入口走同一套 Span 可见性 |
| 三域 `calc_mode` 不同名 | 同一迭代 Monitor / Log 也在补相对计算 | 枚举名对齐；实现仍分域 |
| 老策略被新默认值带偏 | 缺省若变成 `change` | 缺省必须是 `absolute`；兼容用例是发布门禁 |
| 探针安装混进 APM 十月 | 和节点管理抢同一安装通道 | 安装不进本清单；区内 OTLP + 制品与节点管理共背 |

## 8. 明确不做什么

**本月 APM 不做：**

- 告警中心能力：屏蔽、维护窗、级别抑制、降噪聚合、升级链、值班路由。已抄送的事件继续由告警中心运营。
- 把 SkyWalking `silence-period`、Datadog Downtime、SigNoz maintenance 做成 APM 策略字段。
- 通用多条件构造器、条件组嵌套、OR 组合、任意第三条指标。
- 任意查询语言、公式编辑器、自由 PromQL / LogsQL / MQE。
- `yoy` 同比、统计基线、ML / Watchdog 异常、容量预测。
- 新的分位入口（P90）或「关键接口延迟」场景模板（原 #19 的 P1，十一月再说）。
- RUM、Profiling、AIOps、尾采样、Span Metrics、公网 OTLP Token。
- 探针安装器、POC 包装脚本、K8s 语言探针注入、数据面编排、把 `deploy/apm` 当成生产真相源。探针安装归节点管理；区内 OTLP 接入点与探针制品与节点管理共背，不在本清单开新条。
- 用实时追踪库重画历史告警图；改 Alert / Event / 快照生命周期语义。
- 试算或扫描去「预演」告警中心是否屏蔽。
- 三域抽公共 `calc_mode` 库。

**本月也不要混进 APM 的可观测总伞事项：**

- Monitor 的百分位主路径 / 同比 / `timeleft`（见 Monitor 十月规划）。
- Log 的关键字命中改版、自动恢复、样本回跳（见 Log 十月规划）。
- 节点管理的覆盖一览、`push_targets`、批量升级（见节点管理十月规划）。

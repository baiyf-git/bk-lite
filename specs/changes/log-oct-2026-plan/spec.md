# BK-Lite Log 十月迭代规划（PM 优化稿）

Status: proposed  
Audience: 产品 / 研发排期  
Scope: 仅 BK-Lite Log（`web/src/app/log` + `server/apps/log`，VictoriaLogs，Vector / Beat）  
Horizon: 国庆后约 3 周，约 1 组全栈；略满可砍，不再加项

本文是可排期产品稿，不是实现规格。写法样例可参考 PR #18（`docs: Log 告警策略计算方式补齐`）的 `calc_mode` 表述；PR #18 只说明「计算方式怎么写」，不是十月唯一主题。`specs/changes/log-alert-calc-mode/` 当前仓库不存在。

---

## 0. 证据分层

### 仓库事实

- 策略只有两类：`keyword`（命中即告）和 `aggregate`（本窗 `count` / `sum` / `avg` / `max` / `min` 对阈值）。表单与扫描都没有 `calc_mode`，没有对照窗，没有占比。
- 扫描在 `server/apps/log/tasks/services/policy_scan.py`：单窗 LogsQL `stats` 后比阈值。关键字会取样本，默认 `limit=5`；聚合只存 `query_result`，不存原始日志。
- 策略页已有查询联想（`log-policy-query-autocomplete`），当时明确不做服务端试运行。
- 告警详情已能打开检索：`/log/search?query=&startTime=&endTime=&log_groups=`。聚合详情会把 `stats` 拼进查询，值班人看到的不一定是「当时那批日志」。
- IM 通知只有时间、告警内容、策略名，以及指向 `/log/event/alert` 列表的链接；不带样本，也不预填检索。
- 检索页已有组织级「保存 / 加载条件」：`SearchCondition`（名称 + query + 日志分组 + 时间，相对时间靠 `origin_value`）。展示列在浏览器 `localStorage`，不是命名查询的一部分。产品决策已写明：`SearchCondition` 是命名查询，不是用户习惯表。
- 日志告警没有自动恢复。抑制、维护窗、相关性降噪、事故聚合在告警中心。

### 已确认产品决定

- 抑制 / 维护窗 / 降噪运营归告警中心，Log 不做。
- 对外对比口径是「Log 判定 + 告警中心运营」，不是「Log 做成第二套告警中心」。
- 十月需求方法是竞品差距对照，不是只补 `calc_mode` 文档。
- 工作量：国庆后约 3 周、约 1 组全栈；略满可砍，勿再加项。

### 当前假设

- 「错误」由策略里一条错误侧查询表达（级别、状态码、关键字等），平台不内置错误分类器。
- 试算看「现在这套条件套在最近一个完整窗上会怎样」，不是回放历史每一次扫描。
- 告警中心副本继续收结构化生命周期事件；样本正文只保证 Log 详情和 Log 自己发出的 IM / 邮件可读。

### 待确认（不挡排期）

- 变化量对外文案用「较上一窗」还是「环比」。实现都是上一等长窗，十月不引入同比 / 工作日基线。
- 组织级 `SearchCondition` 是否改成「仅自己可见」。十月主保不动它。

## 1. PM 审阅意见

### 1.1 十月要验证的价值

值班和策略配置人现在只能配「这个窗口里有没有日志 / 数字过没过线」。流量涨时误报，流量跌时漏报；配完要等下一个扫描周期才知道对不对；手机上的告警只有一句话，点进去还在告警列表。

十月只补这三段闭环：

1. 策略能说「变快了 / 比上一窗高了 / 错误占比高了」。
2. 配完当场能看到本窗数字、对照或总量、变换后的值、会不会触发。
3. 触发后通知和详情能看见最多 10 条样本，一跳回到当时的查询和分组。

这三件事能直接对上 ELK / Loki / Datadog Logs / 阿里云 SLS 的常用日志告警，而不是对上他们的可观测套件全集。

### 1.2 优先级

| 优先级 | 条目 | 判断 |
|---|---|---|
| P0 主保 | 1 速率 / 变化量 | 没有相对计算，聚合策略只能数绝对条数。这是竞品桌面上的缺口，也是误报 / 漏报的根因。 |
| P0 主保 | 3 试算预览 | 相对计算配错的代价是静默误报。没有试算，第 1 条在真实环境不可交付。 |
| P0 主保 | 4 样本 + 回跳 | 判定闭环的最后一公里。通知现状最弱；详情回跳已有半成品，按「补齐」做，不要重做快照体系。 |
| P1 可砍窄 | 2 错误占比 | 真需求，但是第 1 条引擎上的第三个 `calc_mode`。十月只做 count 占比。 |
| P2 不进主保 | 5 保存查询 | 组织级命名查询已经 GA。再做「个人星标」是产品分叉，不是从零补能力。W3 有余力再做；没有余力直接砍。 |

三域总括仍用：【可观测：告警策略补相对计算 + 配完能验】  
Log 主保：1 + 3 + 4。2 可砍窄。5 不占主保名额。

### 1.3 伪需求（不要当成十月新功能从零做）

1. **「保存查询」当新模块。** 检索页已有星标保存、列表加载、组织隔离的 `SearchCondition`。功能清单已标 GA。十月若重做一套个人星标对象，会和现网查询抢同一入口，3 周里最不值。
2. **「告警附样本」当新存储。** 关键字已经把样本写进 `EventRawData` / 快照，默认 5 条。缺口是：聚合没有样本、通知不展示、默认不是 10、回跳链接不在通知里、聚合回跳可能带上 `stats`。
3. **抑制、维护窗、屏蔽、智能降噪、升级、值班表。** 告警中心已有屏蔽 / 维护窗 / 相关性降噪。写回 Log 会做成两套运营，对比口径立刻乱掉。
4. **异常检测、预测、多基线、手写两条 LogsQL、日志大盘。** 这是成熟度增强，不是 3 周闭环。PR #18 的 `calc_mode` 写法够用，不要借它扩成规则引擎。
5. **日志自动恢复。** 领域决策已后置。十月相对计算仍然是「命中则持续活跃，人工关闭」，不发明恢复。

### 1.4 与告警中心的边界

| 谁做 | 做什么 | 不做什么 |
|---|---|---|
| Log | 用本窗 / 对照窗 / 总量判定该不该响；试算同一套数；把 ≤10 条样本和回跳条件留给值班人 | 不抑制、不设维护窗、不相关收敛、不把噪声运营做成策略字段 |
| 告警中心 | 收日志告警副本后做屏蔽、维护窗、分派、升级、事故、降噪 | 不代替 Log 算速率 / 占比，不改 Log 的触发事实 |

对外只说一句：**Log 负责判定和证据，告警中心负责运营。**  
十月验收不写「维护期不响」——那是告警中心屏蔽策略的验收。  
Log 试算只回答「按当前条件，这一窗会不会触发」，不管告警中心后来是否屏蔽通知。

### 1.5 3 周可交付性

约 1 组全栈、国庆后 3 周，能做完的是「一条计算引擎 + 一张策略表单 + 一个只读试算 + 通知 / 详情补证据」。

| 工作包 | 为什么能进 3 周 | 为什么不能再加 |
|---|---|---|
| 速率 / 变化量 | 现有聚合已会 `stats`；再查一个等长对照窗或除以 `period` 秒数 | 同比、工作日基线、异常检测都是另一条产品 |
| count 占比 | 同引擎第二次查询，只做 count | 对 sum / avg 做占比、让用户手写两条 LogsQL，会把表单和扫描一起撑破 |
| 试算 | 预览 API 调扫描同一套变换，禁止落 Event / Alert / 通知 | 前端自己算、或做成历史回放播放器，都会和线上扫描漂 |
| 样本 + 回跳 | 复用关键字样本链，聚合同窗补取；通知补正文和检索深链 | 不要重做 S3 快照、不要做通知模板编辑器、不要做告警中心富文本 |

略满点在：变化量要双窗、占比要双查询、试算要和扫描共用函数、聚合样本是新查询。这已经够满。  
**结论：主保 1 + 3 + 4 可交付；2 默认按 count 占比做，W2 末仍吃紧就整条滑出；5 默认不排。不要再加项。**

## 2. 竞品差距（只对照十月用得上的）

对照的是「日志策略怎么判定、配完能不能验、响了能不能回到日志」，不是 ELK / Datadog 全家桶。

| 能力 | 现在的 Log | ELK / Kibana | Loki / Grafana | Datadog Logs | 阿里云 SLS | 十月怎么补 |
|---|---|---|---|---|---|---|
| 绝对条数 / 聚合阈值 | 有 | 有 | 有（`count_over_time`） | 有 | 有 | 保持；老策略继续这样 |
| 速率（count / 时间） | 无 | Watcher / ES\|QL 可配 | `rate()` 常用 | 阈值监控常按窗口换算 | 查询统计可配 | **做**。`count / period` |
| 相对上一窗 | 无 | 可与上一区间比 | 要自己写查询 | Change 监控是桌面能力 | 环比 / 同比常见 | **做环比等长窗**。不做同比 |
| 错误占比 | 无 | 要两条查询或脚本 | 两条 metric 查询 | Ratio / formula 监控 | 占比告警常见 | **只做 count 占比** |
| 配完试算 | 无 | 部分模拟 | 弱 | Test monitor | 预检 / 试运行 | **做，且必须走扫描引擎** |
| 通知带样本 | 关键字有存储、IM 不展示 | 上下文常见 | 弱 | 通知里带样本日志 | 上下文日志 | **补 IM / 详情展示，上限 10** |
| 回到检索 | 详情有，通知没有；聚合可能带 `stats` | Discover 链接 | Explore 链接 | View logs | 一键检索 | **通知和详情都回跳；预填查询、分组、触发窗** |
| 保存查询 | 组织级已有 | Saved search | Saved query | Saved view | 已存查询 | **十月不重做** |
| 抑制 / 维护窗 | 告警中心 | Mute | Silence | Downtime | 静默 / 维护窗 | **Log 不做** |

缺口不是「没有日志告警」，而是「没有相对计算、不能先验、通知没有证据」。

## 3. 优化后的十月清单

【可观测·日志：策略能配相对计算，配完能试算，告警能带样本回跳】

1. 策略计算方式：速率 / 变化量（对照上一等长窗口；缺对照不误报）
2. 策略计算方式：错误占比（仅 count；错误侧查询 vs 同窗总量；总量为 0 不触发）
3. 策略条件试算预览（本窗 / 对照或总量、变换后值、是否触发；复用扫描引擎，不落告警）
4. 告警通知与详情附日志样本（≤10 条）+ 一跳回检索（预填查询、日志分组、触发时间窗）
5. （不进主保）保存查询维持现网组织级条件；个人星标仅 W3 余力，不做大盘、不新建第二套查询对象

主保：1 + 3 + 4。  
2 与 1 共用 `calc_mode`，只做 count 占比；W2 末仍吃紧则整条不做。  
5 默认不排。

## 4. 逐条说明

### 4.1 速率 / 变化量

**用户价值：** 流量涨的时候，不再只因为「窗口里条数变多了」就响；要看单位时间速率，或是不是比上一窗真的变了。

**做什么：** 聚合策略增加计算方式。速率 = 本窗统计值 ÷ 检测周期秒数。变化量 = 本窗 − 上一等长窗。对照窗写不出来或没有数据，本轮不触发。未选计算方式的老策略，继续按本窗绝对值比阈值。关键字策略不提供这两种计算方式。

**验收：**

- 策略表单能选「绝对值 / 速率 / 变化量」；老策略打开仍是绝对值，保存后扫描结果与现在一致。
- 速率：同一查询在 5 分钟窗里 300 条，变换后值为 1 条 / 秒；阈值按变换后的值比。
- 变化量：本窗 120、上一窗 80，变换后值为 40；上一窗查询失败、无数据或窗口尚未形成，本轮不建告警、不发通知。
- 分组策略按组对齐对照窗；对不上的组按「缺对照」处理。
- 用户不能手写第二条 LogsQL 来表示对照窗。

**非目标：** 同比、周同比、工作日基线、异常检测、预测、关键字策略做速率、把抑制次数做成计算方式。

**依赖：** 只依赖 VictoriaLogs 双窗查询和现有 `period`。不依赖告警中心。告警中心继续收触发后的副本。

### 4.2 错误占比（可砍窄）

**用户价值：** 错误条数跟着流量涨时，值班看的是「错得是不是更密了」，不是「今天请求更多了」。

**做什么：** 同一 `calc_mode` 增加「占比」。配置人填一条错误侧查询；总量 = 同一日志分组、同一窗口、去掉错误过滤后的 count。占比 = 错误 count ÷ 总量。总量为 0 不触发。不做 sum / avg / max / min 占比，不让用户手写两条 LogsQL。

**验收：**

- 表单是「错误查询 + 计算方式 = 占比」，没有第二个 LogsQL 编辑器。
- 错误 20、总量 200，变换后值为 10%；总量 0，试算和扫描都是「不触发」，并写明原因是总量为 0。
- 与第 1 条共用扫描变换；老策略不受影响。

**非目标：** 平台内置错误分类、多条错误查询、对非 count 做占比、把占比当关键字策略的模式。

**依赖：** 第 1 条的 `calc_mode` 与扫描变换先落地。不依赖告警中心。告警中心不负责算占比。

**砍法：** W2 末引擎或试算仍不稳，整条不做，不改成「先让用户填两条查询」。

### 4.3 策略条件试算预览

**用户价值：** 配完立刻知道「按现在的数据，这一窗会不会响」，不用把半成品策略开到生产上等下一个周期。

**做什么：** 策略页提供试算。预览 API 必须走扫描同一套取数、对照窗、变换和阈值判断。只读：不写 Event、Alert、快照，不发通知，不推告警中心。页面至少给出本窗值、对照值或总量、变换后值、是否触发、不触发原因（缺对照 / 总量为 0 / 未过阈值 / 查询失败）。

**验收：**

- 同一草稿条件，试算「是否触发」与下一次真实扫描在同一时间窗上的结论一致。
- 缺对照、总量为 0、查询失败时，试算明确说「不触发 + 原因」，不会显示成触发。
- 前端不得用本窗数字自己算速率 / 变化量 / 占比来决定是否触发。
- 无日志分组或查询为空时，试算不可用，但不挡保存绝对值老策略。
- 试算失败只留在策略页，不产生告警噪声。

**非目标：** 查询语法校验器、历史回放时间轴、一次试算写入告警、按告警中心屏蔽规则预演「会不会通知」。

**依赖：** 第 1 条（以及若未砍的第 2 条）的变换逻辑先可复用。与告警中心无功能依赖；试算结果不考虑屏蔽 / 维护窗。

### 4.4 样本 + 一跳回检索

**用户价值：** 手机上看告警就能看见当时几条日志，点一下回到检索，而不是先打开告警列表再猜时间窗。

**做什么：** 触发快照统一最多 10 条样本。关键字沿用现有样本链，默认上限从 5 提到 10。聚合在同一查询和触发窗内补取最多 10 条原始日志，不再只给一行 `stats`。Log 自己的 IM / 邮件展示这些样本（渠道截断时至少留下条数和回跳）。通知和详情的回跳打开检索，并预填：策略查询（不要带 `stats`）、策略日志分组、触发窗口。详情里现成的回跳按同一套规则改，避免聚合跳进一条统计语句。

**验收：**

- 关键字和聚合触发后，详情都能看到 ≤10 条样本；没有样本时说明「本窗无原始日志」而不是空白。
- IM / 邮件能看到样本摘要，并有一条打开检索的链接；点开后查询、分组、起止时间与触发窗一致。
- 回跳查询是策略里的过滤条件，不包含扫描用的 `stats`。
- 样本取失败不阻断告警创建和通知；通知仍有回跳。
- 不把完整 payload、凭据或无界原文打进生产日志。

**非目标：** 重做快照存储、通知模板编辑器、告警中心卡片改版、自动恢复、在 Log 里做屏蔽。

**依赖：** 现有 `EventRawData`、检索 URL（`query` / `startTime` / `endTime` / `log_groups`）、系统管理通知渠道。告警中心：副本协议不因样本变长而改语义；告警中心页面带不带样本不是本条验收。屏蔽后通知被压住，是告警中心行为，Log 仍保存样本。

### 4.5 保存查询（不进主保）

**用户价值：** 个人常用检索能一键回到「查询 + 相对时间 + 列」。现网已经能保存组织级条件；缺的是「只属于我」和列一起存。

**做什么（仅 W3 余力）：** 在现有 `SearchCondition` 上加「仅自己可见」，并允许把当前展示列写进 `condition`。入口仍是检索页星标 / 加载，不新做查询中心，不做组织共享改造，不做大盘。

**验收（只有真做时才算）：**

- 个人条件只有创建人在当前组织能加载；组织级旧数据仍按现网可见。
- 加载后恢复查询、日志分组、相对时间、展示列。
- 不出现第二套「星标查询」模型或菜单。

**非目标：** 组织共享重构、查询市场、仪表盘、把命名查询迁进用户习惯表。

**依赖：** 现成 `SearchCondition`。与告警中心无关。

**砍法：** 默认整条不排。主保或占比吃紧时直接砍，不做到「只改文案」。

|---|---|---|
| W1 | `calc_mode`：绝对值兼容、速率、变化量；扫描双窗；缺对照不触发；策略表单能选 | 不做同比、不做占比 |
| W2 | 试算 API + 策略页预览；若 W1 稳定，接 count 占比 | 试算与扫描结论不一致则停占比，先修引擎 |
| W3 | 样本上限 10、聚合补样本、IM / 详情展示、回跳预填查询 / 分组 / 触发窗 | 个人星标只在 1+3+4 已验收时碰；否则不开工 |

并行约束：第 3 条不能等第 4 条；第 2 条不能先于第 1 条；第 5 条不能和第 4 条抢最后几天。

## 6. 风险与建议砍法

| 风险 | 为什么会发生 | 十月怎么处理 |
|---|---|---|
| 双窗 / 双查询把扫描拖慢 | 变化量和占比都会多打 VictoriaLogs | 对照窗失败 = 不触发，不重试到误报；占比默认只 count；超时记失败原因，不补绝对阈值 |
| 试算和线上扫描各写一套 | 前端或预览接口图省事 | 验收写死「同一函数」；发现双实现就停占比，先收口 |
| 把第 4 条做成新快照产品 | 聚合今天没有原始日志，容易重做存储 | 只补取样本和改通知 / 回跳；S3 快照结构不换 |
| 把第 5 条当主功能 | 组织级保存已经在 | 默认不排；余力也只加个人可见 + 列，不新建对象 |
| 相对计算配完没有试算 | 变化量 / 占比比绝对值更难目测 | 第 3 条是主保，不能为了做占比而挤掉试算 |
| 通知带 10 条样本被渠道截断 | IM 有字数上限 | 正文截断仍保留条数和回跳；不为此做模板平台 |
| 范围滑向告警运营 | 「维护期别响」会被当成日志需求 | 文档和验收都不写抑制 / 维护窗；对比口径保持「Log 判定 + 告警中心运营」 |
| 老策略被新默认值带偏 | `calc_mode` 缺省若变成速率 | 缺省必须是现在的绝对值；兼容用例是发布门禁 |

建议砍法，按顺序用，不要同时砍主保的两头：

1. 先砍第 5 条（默认就不做）。
2. 再砍第 2 条整条（不要改成手写双查询）。
3. 第 4 条若只剩一天：只做通知回跳 + 关键字样本展示到 10 条；聚合样本和下个迭代。
4. 不砍第 1 条的变化量「缺对照不误报」，不砍第 3 条。没有这两条，相对计算不能上生产。
5. 任何情况下都不把抑制、维护窗、降噪、自动恢复、异常检测、大盘加进十月。

## 7. 明确不做（整月）

- 抑制、静默、维护窗、屏蔽、智能降噪、升级策略、值班表。
- 日志告警自动恢复、转派、告警中心处理人回写。
- 异常检测、预测、同比、工作日基线、多基线。
- 手写两条 LogsQL、通用规则引擎、查询语法校验器。
- 日志大盘、组织共享查询中心、把命名查询改成用户习惯。
- 为了「灵活」把试算或扫描放到前端重算。

十月结束时，对外可讲的仍是一句人话：策略能配相对计算，配完能试算，告警能带样本回到检索。运营降噪继续在告警中心。

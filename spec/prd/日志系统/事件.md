# 日志系统 · 事件

## 1. 背景与目标

事件是日志侧的告警能力：用户通过策略定义基于日志模式/计数的触发条件，系统周期评估并生成告警，用于从日志中发现异常。

## 2. 范围定义

- 告警：列表、筛选、关闭、原始事件查看。
- 策略：基于日志的告警策略的新增、编辑、删除、启停。

## 3. 关键能力

### 3.1 告警

- 支持告警列表查看，按状态、级别、采集类型、时间范围、策略名筛选。
- 支持关闭告警（需具备该告警的操作权限）、查看关联事件与原始事件数据快照。
- 告警名称支持 `${字段名}` 占位符，系统在告警命中时按各分组的字段值渲染，列表与详情展示渲染后的名称。

### 3.2 策略

- 支持基于日志的告警策略增删改与启停。
- 触发条件基于日志模式查询 + 聚合规则（分组字段、计数/数值阈值比较），在数据窗口内满足条件则触发（如"最近 5 分钟错误数 > 10"）。
- 关键字告警支持按分组字段（group_by）拆分：系统对每个分组独立产生一条告警并保留各自的事件样本，告警名称中的占位符按该分组的字段值渲染。
- 策略作用于所选日志分组，可全局或按采集类型。
- 支持配置检测频率与回看周期、告警名称与级别、可选的通知渠道与接收人。
- 支持启停，并记录最近执行时间。

### 3.3 通知可靠性

- 通知发送具备 at-least-once 语义：通道出现瞬时故障时自动内联重试，发送失败的事件由周期补偿任务自动重新投递，补偿窗口默认覆盖近 24 小时内的失败记录。
- 通知去重：同一活跃告警在已成功通知后、告警级别未发生变化期间，不重复发送通知；告警级别升/降时重置通知状态并触发一次新通知。

## 4. 关键规则

- 日志策略基于日志计数/模式（文本）触发，绑定日志分组；区别于监控模块基于指标阈值（数值时序）的策略。
- 策略、分组、实例按组织隔离，受权限控制。
- 关闭告警需具备该告警归属组织的操作权限，非授权用户操作将被拒绝。
- 单条告警生命周期内的原始日志快照保留最新 500 条，超限自动丢弃最旧条目，防止对象存储过度膨胀。

## 5. 关键技术架构选择

- 策略评估由 Celery 定时任务周期驱动。
- 告警原始数据与累积事件快照以压缩 JSON 存于对象存储（单告警快照上限 500 条）。
- 通知可靠性由内联重试 + 静态 Celery beat 周期补偿任务共同保障，语义为 at-least-once。

## 6. 验收标准

- 用户可创建基于日志的告警策略并配置触发条件、周期与通知。
- 系统按周期评估日志并正确生成告警；关键字告警在配置分组字段时可按分组各产一条告警。
- 告警可查看关联事件与原始数据，并由授权用户关闭。
- 通知在通道瞬时故障时能自动重试并由补偿任务补发；同一活跃告警已通知后不重复发送（级别变化除外）。

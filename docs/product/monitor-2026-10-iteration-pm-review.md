## 1. 产品判断

十月 Monitor 只补**策略判定**：算出可比值、比阈值、当场验会不会响。运营侧继续交给告警中心。草案方向对，但 5 条把两件不该并列的事写进同一条，又把「环比 5m」和「变化量」叠在一起；3 周略满，必须按主题砍到「相对计算 + 能验」先闭环。

### 2.3 3 周容量：砍 / 合 / 排序

PR #17 全套（同比、基线、容量预测、公式函数）远超 3 周。草案 5 条若都当 P0，会做成半套相对计算、试跑落空。

| 序 | 条目 | 3 周位置 | 理由 |

### 2.4 草案缺什么

原文 5 条只有能力名，没有背景、价值、验收、实现要点，排期时无法卡「做完长什么样」。第 3 节按条补齐，规划会里只贴第 0 节即可。

### 2.5 和 APM / Log 怎么统一语言、又不重复造运营

三域都补「计算方式」，**只对齐用词，不对齐实现，不抽公共扫描库**。十月只在 Monitor 落地百分位主路径；APM 的 P95 已是指标类型，Log 的百分位在 #18 里是 P2。

| 用户看见的词 | 含义（三域同一句话） | Monitor 十月 | APM（#19，不在本迭代硬做） | Log（#18，不在本迭代硬做） |
|---|---|---|---|---|
| 计算方式 | 窗口数字怎么变成拿去比阈值的值 | 要上 | 要上，按 RED 裁 | 要上，按 LogsQL 计数裁 |
| 固定阈值 | 当前窗绝对值比固定数 | 存量缺省 | 存量缺省 | 聚合缺省 |
| 百分位 | 窗口分布的 P90/P95/P99 | **主路径** | 已是 `metric_type`，不要再做 `calc_mode=percentile` | P2，不做十月 Monitor 的事 |
| 变化量 | 相对**上一等长窗**的 Δ 或 % | **主路径** | P0 | P0（速率/突增） |
| 环比 | 相对用户选的对照窗，阈值是 % 或倍数 | 对照 **1h/1d** | 短对照（上一窗/1h/1d） | 短环比偏 P1 |
| 对照缺失不误报 | 对照窗没数据，本轮不触发，不当 0 | 必须 | 必须 | 必须 |
| 预览 | 看变换后的曲线/对照 | 已有曲线预览，要跟计算方式走 | 已有 | 已有 |
| 试跑 | 选对象，问「现在会不会响」，不落单 | **本迭代做** | 可后续同名；用本域引擎 | 可后续同名；用本域引擎 |

运营词（静默、维护窗、抑制、升级、编排）三域都不要在策略页新造一份。

## 3. 定稿逐条：背景 / 做什么 / 怎么实现 / 验收

### 1，策略计算方式：百分位（P90/P95/P99），只放告警条件一个入口

- **背景：** 策略页窗口算法只有 avg/max/min/sum/count/last，没有 `quantile_over_time`。腰部客户要配「延迟 P95 > 200ms」，只能拿均值硬套或不会写的 PromQL。APM 已有 P95 指标类型；Monitor 是 Gauge/时序窗口分位，不是追踪分位。
- **做什么：** 告警条件增加「计算方式」，默认「固定阈值」。选「百分位」后只出现 P90/P95/P99。定义指标仍只负责取哪条序列、窗口怎么聚合，**不要并排再放 P95**。
- **怎么实现：** 按 #17：`calc_mode` 落策略；`percentile` 编译 `quantile_over_time`；预览与扫描共用编译；存量无字段当 `absolute`。非法分位保存期拒绝。现有四则公式的结果序列可以套百分位；不扩展公式语言。
- **验收：** 新建默认固定阈值；旧策略不改保存则扫描与现在一致；P95 策略按分位序列比阈值；定义指标列表仍无 P90/P95/P99；用户不用写 PromQL。

### 2，策略计算方式：变化量（上一窗）+ 环比（对照 1h/1d）

- **背景：** 绝对值会把早高峰、发布窗口当成故障。客户要的是「比刚才多了多少 / 比上一小时、昨天同时段高多少」。#17 写的 1d/7d 偏长周期，和 APM/Log 短对照、以及基础设施毛刺场景都不贴；草案 5m 又和「上一窗」重复。
- **做什么：** 「变化量」= 相对上一等长汇聚窗，阈值用 Δ 或 %。「环比」= 对照 1h 或 1d，阈值用涨跌幅 % 或倍数。对照窗缺失：本轮不触发，不当 0。
- **怎么实现：** 在窗口聚合之后、阈值比较之前做双查询或 `offset`。`change` 与 `mom` 保存值必须不同。预览同时画出当前值与对照值，阈值线按变换后量纲。`1h/1d` 超出 VM 留存时保存/预览说明，不静默当 0。十月不做 7d、30d、同比、基线。
- **验收：** 两种模式可保存、预览、扫描；上一窗或 1h/1d 缺失不误报；阈值单位随模式切换；表单不出现「环比 5m」（避免与变化量重复）。

### 3，策略条件试跑：选实例看是否触发，复用扫描引擎，不落告警、不通知

- **背景：** 现网只有指标曲线预览，没有「这套条件现在会不会响」。相对计算上线后，对照缺失、量纲切换更容易配错。腰部客户私有化，配完不敢开，只能干等扫描。
- **做什么：** 策略页（含未保存草稿）选授权范围内的实例，点「试跑」，看到每个实例：会触发 / 会恢复 / 无数据 / 对照缺失 / 样本不足，以及用于比较的当前值、对照值、阈值。
- **怎么实现：** 复用 Monitor 扫描的查询编译 + `AlertDetector` 判定，包一层只读试跑，不写 `MonitorAlert` / `MonitorEvent` / 快照，不发本域通知，不投告警中心。权限与策略可见实例一致，fail-closed。曲线预览仍叫「预览」，本条叫「试跑」，不要混成一个按钮。
- **验收：** 同一套 P95/环比条件，试跑结论与下一次真实扫描一致（同一时刻、同一实例）；试跑后告警列表、通知、告警中心无新记录；越权实例不可选、不可出数。

### 4，独立恢复阈值（滞回）；无数据检测窗/恢复窗在表单拆开

- **背景：** 恢复今天是「连续 N 个周期不再满足**同一条**触发阈值」（`recovery_condition`）。CPU 在 79～81 抖动会振铃。无数据：模型已有 `no_data_period` 与 `no_data_recovery_period`，前端保存写成同一个值，恢复窗配不了更短。
- **做什么：** 触发与恢复可以是两个阈值（如触发 >80、恢复 <70）；未填恢复阈值时行为与现在相同。无数据表单拆成「检测窗」「恢复窗」，允许恢复窗更短。这是域内告警状态何时翻回，不是告警中心静默。
- **怎么实现：** 恢复比较走变换后的值，连续周期语义保留。无数据只改表单绑定，不要动 `PolicyInstanceBaseline` 的无数据库存语义，也不要在定义指标里再开一套百分位。
- **验收：** >80 触发、<70 才恢复，70～80 保持活跃；不填恢复阈值时与改前一致；无数据检测 10m、恢复 2m 可分别保存并按各自窗口扫描。本条若与试跑抢工时，整条降级，不拆一半上线。

## 4. 明确不做（写进规划「非范围」）

- 告警中心：维护窗、静默、级别抑制、通知编排、升级分派、告警中心侧试跑。
- 表达式：Zabbix Trigger、自由 PromQL、任意分位滑条。
- #17 后段：同比、统计基线、容量预测、公式函数库、ML。
- 结构：三域公共计算库；试跑落库或发通知；把无数据库存表拿来做统计基线。
- 本迭代不重做：域内处理人 / 认领 / 分派、通知渠道、策略公式编辑器本身。

## 6. 证据（仓库事实，不是愿望）

- 窗口算法无分位：`WINDOW_AGGREGATION_ALGORITHMS` 与 `useMethodList` 只有 avg/max/min/sum/count/last。
- 恢复只有连续周期、同一阈值：`MonitorPolicy.recovery_condition`，`AlertDetector.recover_threshold_alerts`。
- 无数据双字段已被前端写死成同一个：`page.tsx` 中 `no_data_recovery_period = no_data_period`；表单只露一个检测时长。
- 预览已有、试跑没有：`previewMonitorPolicy` / `metricPreview.tsx`；无试跑入口。
- 分工：Monitor 扫描产生域内告警并投影告警中心；屏蔽/分派/升级在告警中心。见 `CONTEXT.md` 领域告警、`docs/design-docs/monitor-module-architecture-analysis.md`、`docs/design/product-decisions/domain-alert-handlers.md`。
- 需求底稿：#17 写清 `calc_mode` 与非范围；#18/#19 要求三域同词、各算各的。十月 Monitor 吃 #17 的 V1a + 短对照 V1b，不吃全表。

## 7. 给群聊的短结论

十月 Monitor 定稿 4 条：P95 只留一个入口；变化量=上一窗、环比=1h/1d（去掉会撞车的环比 5m）；试跑提到必须交付且不落单；滞回+无数据双窗并成第 4 条，抢工时先砍。抑制类继续只进告警中心。3 周保「相对计算 + 能验」。

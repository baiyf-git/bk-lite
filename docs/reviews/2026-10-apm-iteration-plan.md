## 1. 审核意见

### 1.1 做得好的

- **主题方向对。** 「策略能配相对计算、配完能验」能被售前和客户听懂，也对齐可观测三域（Monitor / APM / Log）同一套产品语言。
- **告警中心边界写对了。** 屏蔽、维护窗、降噪、升级运营不进 APM 十月。仓库事实也支持：APM 拥有判定与域内生命周期，事件副本单向抄送告警中心，告警中心不得回写。见 `CONTEXT.md`「领域告警 / 告警中心事件」、`specs/capabilities/apm-alerting.md`、`docs/design/product-decisions/domain-alert-handlers.md`。
- **`calc_mode` 是真缺口，不是发明。** 现状 `ApmPolicy` 只有 `error_rate / p95 / p99 / throughput / no_traffic`，窗口聚合后比固定阈值。PR #19 已把问题、裁剪和「对照缺失不误报」写清，并与 Monitor #17、Log #18 对齐语言。
- **Trace 隔离是真债，不是凑数。** 列表已按组织后过滤；详情只要有一条可见 Span，就整链返回。这是越权，不是体验优化。
- **明确不做写得干净。** RUM、Profiling、AIOps、任意 QL、接入包装脚本、告警中心运营，都不该进这个月。

### 1.2 有问题的

1. **主题一次装了三件事。** 「环比 / 多条件 / Trace 不越权 / 试算」并列后，干系人分不清十月主卖点。主卖点应是：**相对计算能配、配完能验**；Trace 不越权是必须修的信任债，单独成条，不要写进主题中心词。
2. **把 PR #19 当成十月唯一主题会偏。** `calc_mode` 是方法样例。十月还应消化已经暴露的探索权限债，以及腰部客户最高频的「低流量误报」门槛。但后两者不能和相对计算抢同一套「通用引擎」叙事。
3. **「多条件 AND/OR」写得过宽。** 竞品里 Datadog Composite、SkyWalking MQE `&&`、ARMS 多条件都存在；BK-Lite 的产品纪律是表单枚举、禁止任意表达式。十月只该交付 **一个高频模板**：错误率或时延告警可同时要求最低吞吐。不要做通用布尔构造器。
4. **「策略试算」和现有「指标预览」没切开。** 策略页右侧已经有 `test_query` 预览当前值与序列。十月要补的不是第二张图，而是：**当前值、对照值、变换后比较值、会不会告、不告的原因**。试算应写成第 2 条的验收，而不是第五个独立史诗。
5. **探索分页正确性价值低于前三条。** 9 月已做 Trace 列表分页与容量提示，后过滤游标也有实现。若没有可复现的「翻页丢行 / 重复 / 越权游标」，应降为可砍项，不要和相对计算抢全栈带宽。
6. **条目粒度不像九月正文。** 九月写法是「模块说人话主题 + 编号具体能力」。草稿更像缺口清单，缺背景一句、验收和人话交付物。

### 1.3 风险

| 风险 | 为什么会炸 | 产品处理 |

## 2. 优化后的十月规划正文（可粘贴）

### 【可观测：告警策略补相对计算 + 配完能验】

十月可观测总主题：Monitor / APM / Log 都让腰部客户用表单表达「比刚才 / 比上一窗」，并且保存前能看见会不会告。三域共用计算方式语言（`absolute` / `change` / `mom`），各自作用在本域序列上，不共用查询引擎。屏蔽、维护窗、降噪、升级仍在告警中心。

- **监控中心：** 按 Monitor #17 的 P0/V1 批次，先开放已达成共识的相对计算与预览。
- **日志中心：** 按 Log #18 的 P0，先开放速率 / 变化量（及已拍板的占比），对照缺失不误报。
- **APM：** 见下一节。相对计算是主交付；跨组织 Trace 隔离是必须同时收口的信任债。

---

### 【可观测·APM：相对变化能配、配完能验；看不见的调用不漏】

#### 1. 跨组织 Trace 隔离：看得见的 Span 不得带出整条越权调用链

- **背景：** 探索列表已经按组织丢掉不可见行，但打开详情时，只要调用链里有一条本组织 Span，整条 Trace（含其他组织的服务名、耗时、属性）会一起回来。
- **做什么：** 用户只能看到自己组织可见的 Span。不可见 Span 不出现在瀑布图、火焰图、列表、属性、计数里。没有可见 Span 的 Trace 继续 404，不可枚举。从可见 Span 点进详情，只能看到可见片段；上游被裁掉时只提示「部分调用不可见」，不补出被裁服务的名字。
- **验收：**
  - 组织 A 可见、组织 B 不可见的同一条跨服务 Trace：A 的详情里没有 B 的 Span / 属性 / 名称；`span_count` 只计可见。
  - 用 B 的 `trace_id` 直接打详情：404，与「不存在」不可区分。
  - 列表、Span 探索、错误样本下钻走同一套可见性，不能一个入口漏、另一个入口堵。
  - 敏感属性脱敏不回退。
- **建议实现要点（产品级）：** 详情授权从「有一条可见就整链放行」改为「按 Span 裁剪后再返回」。列表后过滤保持。不要靠前端藏节点。拓扑若仍按全链聚合，本条一并改成只聚合可见边，避免详情已裁、图上仍出现不可见服务。

#### 2. 策略计算方式：变化量与短环比，对照缺失不误报

- **背景：** 腰部客户现在只能写「5 分钟错误率 > 5%」。大促或夜间流量一变就误报。Datadog / ARMS 都能用表单配变化量和环比；我们扫描侧已能取出 RED 序列，表单没开放。PR #19 是本条的需求来源，不是全部十月工作。
- **做什么：** 在策略「告警条件」增加计算方式，与 Monitor / Log 同名：
  - **固定阈值 `absolute`：** 新建默认；存量无字段按此扫描，行为与改前一致。
  - **变化量 `change`：** 当前窗口相对上一相邻窗口的 Δ 或涨跌幅%；用于「这 5 分钟错误率比上一窗高 3 个百分点」。
  - **短环比 `mom`：** 对照枚举为上一窗 / 1 小时 / 1 天（APM 短历史，不做 Monitor 的 7 天）。比较方法为涨跌幅% 或倍数。
  - **无流量** 只允许 `absolute`，保存相对计算时直接拒绝。
  - 连续触发 / 恢复 / 无数据继续有效，比较对象改为变换后的值。对照缺失 ≠ 无数据。
- **验收：**
  - 计算方式选择器出现在告警条件；切换后阈值量纲跟着变（绝对值 / Δ / % / 倍数）。
  - 用户不写 PromQL、LogsQL、公式。
  - 对照窗或上一窗缺失：本轮不触发，不当 0，不写成无数据告警。
  - 非法组合（含 `no_traffic` + `change`/`mom`）保存期拒绝。
  - 已有五类指标、多级阈值、处理人、通知、告警中心抄送不回归。
- **建议实现要点（产品级）：** 计算发生在「窗口聚合之后、比阈值之前」。对照偏移用枚举，不让用户手写 `offset`。预览与扫描共用变换。快照仍只记用于比较的变换后值，不改 Alert / Event 生命周期。P95/P99 仍是指标类型，不要再做一套 `calc_mode=percentile`。同比、统计基线、ML 异常本月不出表单。

#### 3. 策略试算：当前值、对照值、会不会告（复用扫描引擎）

- **背景：** 配完不能验，相对计算更不敢开。现有右侧预览只回答「现在是多少」，不回答「按这个规则现在会不会告」。这是相对计算的验收，不是新模块。
- **做什么：** 策略编辑器在现有预览上增加试算结论，而不是新开试算页：
  - 展示当前窗口值、对照窗口值（若有）、变换后比较值、命中的级别。
  - 明确四种不触发原因：**未越线 / 对照缺失 / 窗口无数据 / 未达到连续触发次数**。
  - 查询失败单独提示「取数失败」，不得装成无数据或对照缺失。
- **验收：**
  - 同一组配置，试算「会触发」当且仅当扫描引擎用同一时刻判定也会触发。
  - `change` / `mom` 能同时看到现在 vs 对照；对照缺失时结论为不触发，原因可读。
  - 未保存的草稿可试算；试算不写 Alert、不发通知、不抄送告警中心。
  - 试算不展示、不预测告警中心屏蔽 / 维护窗 / 升级结果。
- **建议实现要点（产品级）：** 按钮文案用「试算会不会告」，避免和「指标预览」抢词。连续次数可在试算里按「若这是第 1 次命中」说明，不要假装能预知过去 N 个周期的历史状态——若历史状态拿不到，就写「按当前窗口，已满足阈值，仍须连续 N 次才会产生告警」。

#### 4. 最低流量门槛：错误率 / 时延告警可同时要求最低吞吐

- **背景：** 绝对错误率和相对变化在低流量下都容易误报（1/5 就是 20%）。ARMS 最佳实践就是「错误率 AND 调用次数 ≥ N」。这是竞品多条件里腰部客户真正会配的那一条，不是通用 AND/OR。
- **做什么：** 当主指标是错误率、P95 或 P99 时，提供可选开关「同时满足最低吞吐」，填一个吞吐下限。打开后，主条件与最低吞吐 **同时满足** 才算命中。不提供 OR，不加第三条任意指标，不做条件组嵌套。
- **验收：**
  - 错误率 > 5% 且 5 分钟吞吐 < 门槛：不告。
  - 错误率 > 5% 且吞吐达标：告。
  - 主条件是 `change`/`mom` 时，门槛仍看 **当前窗口吞吐绝对值**，不看吞吐的环比。
  - 主指标为吞吐或无流量时，不出现该开关。
  - 试算同时展示主条件与门槛是否满足。
- **建议实现要点（产品级）：** 产品上这是主条件的护栏，不是第二条对等策略。通知标题 / 告警内容需能看出「因未达最低吞吐未告」或「主条件 + 吞吐门槛同时命中」。不要顺手做「错误率 OR 时延」。若第 3 周末仍未开工，整条降级到十一月，不得用半成品表达式顶上。

#### 5. 探索后过滤分页正确性（可砍）

- **背景：** 组织后过滤发生在存储分页之后，游标一旦跟存储页绑死，就会漏行、重复或提前结束。9 月已修一轮列表分页；本条只收可复现的正确性，不重做探索。
- **做什么：** 只修调用链 / Span / 错误探索在「后过滤 + 翻页」下的漏行、重复、提前没下一页。容量上限与「近窗样本 ≠ 窗内全量」口径保持 9 月结论。
- **验收：** 构造「存储页大量不可见、可见行跨多页」时，连续翻页不丢可见行、不重复、结束时无下一页。不得为凑满一页放宽组织过滤。
- **建议实现要点（产品级）：** 先用失败用例证明还在漏，再开做。若研发现状测不过例，本条从十月正文拿掉，记入质量债，不占相对计算时间。

## 3. 三周排期与可砍项

假设：国庆后约 3 周、**一个全栈小组**、并行 Monitor/Log 的 `calc_mode` 但不共用实现。略满，必须预留砍刀。

| 周次 | 保底交付 | 说明 |
|---|---|---|
| 第 1 周 | 第 1 条 Trace 隔离；第 2 条模型 + `change` 扫描骨架 | 信任债先收口，避免相对计算做完还不敢给跨组织客户看调用链 |
| 第 2 周 | 第 2 条 `mom` + 对照缺失；第 3 条试算结论上预览 | 这周结束必须能对外演示「配环比 → 看见会不会告」 |
| 第 3 周 | 第 2–3 条打磨与存量兼容；有余量再做第 4 条最低吞吐门槛 | 第 5 条默认不排期 |

**必须保住（砍到只剩这些也算十月成功）：**

1. Trace 详情不再越权。
2. `absolute` 兼容 + `change` + 短 `mom`，对照缺失不误报。
3. 试算能回答会不会告，且与扫描一致。

**有余量再做：** 第 4 条最低吞吐门槛（单模板）。

**容量不够先砍（顺序）：**

1. 第 5 条探索分页——默认砍。
2. 第 4 条最低吞吐门槛——整条移十一月，禁止改成通用 AND/OR 残骸。
3. `mom` 的「1 天」对照——只留上一窗和 1 小时，降低留存与双查询成本。
4. 试算里的连续次数解释——可先只给当前窗口是否越线，文案写清「连续次数以扫描为准」。

**不要用「各做一半」换看起来条目多。** 宁可十月只有隔离 + 变化量 + 试算闭环。

依赖：

- 第 3 条依赖第 2 条的变换已存在；不要先做独立试算页。
- 第 4 条依赖第 2–3 条的判定出口稳定；否则门槛会和相对计算各算各的。
- 第 1 条与策略工作无产品依赖，可并行，但不要拖过第 1 周。

## 4. 明确不做什么

**本月 APM 不做：**

- 告警中心能力：屏蔽、维护窗、级别抑制、降噪聚合、升级链、值班路由。已抄送的事件继续由告警中心运营。
- 把 SkyWalking `silence-period`、Datadog Downtime、SigNoz maintenance 做成 APM 策略字段。
- 通用多条件构造器、条件组嵌套、OR 组合、任意第三条指标。
- 任意查询语言、公式编辑器、自由 PromQL / LogsQL / MQE。
- `yoy` 同比、统计基线、ML / Watchdog 异常、容量预测。
- 新的分位入口（P90）或「关键接口延迟」场景模板（PR #19 的 P1，十一月再说）。
- RUM、Profiling、AIOps、尾采样、Span Metrics、公网 OTLP Token。
- 接入 / POC 包装脚本、数据面编排、把 `deploy/apm` 当成生产真相源。
- 用实时追踪库重画历史告警图；改 Alert / Event / 快照生命周期语义。
- 试算或扫描去「预演」告警中心是否屏蔽。

**本月也不要混进 APM 的可观测总伞事项：**

- Monitor 的百分位 / 同比 / `timeleft`。
- Log 的关键字命中改版、自动恢复状态机。

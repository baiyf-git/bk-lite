# 监控告警计算覆盖

- 最近更新：2026-09-14
- 当前规格：本文即覆盖地图。十月施工入口 [`specs/changes/monitor-oct-2026-plan/spec.md`](../../../specs/changes/monitor-oct-2026-plan/spec.md)；四域总揽 [`specs/changes/oct-2026-plan/overview.md`](../../../specs/changes/oct-2026-plan/overview.md)。近期待办以「必做」为准，不另开施工单。

## 产品定位

监控策略用表单表达「这个指标怎样算、怎样比线」，让腰部客户能配固定阈值、尾部分位和「比刚才 / 比 1 小时前」，保存前能看见会不会告。这不是 Zabbix 触发器函数全集，也不是第二套 PromQL。

仓库里 Zabbix 是告警中心接入源，不是监控策略的对标实现。对外不写「告警计算对齐 Zabbix」。

## 档位（承诺强度）

附件列出全部计算方式，**档位才是承诺**。未标「必做」的不视为近迭代范围。工时只决定哪一档先做，不把条目从需求里删掉。


| 档       | 含义             | 交付承诺           |
| ------- | -------------- | -------------- |
| **保持**  | 现网已有，不回退       | 回归，不新开需求       |
| **必做**  | 腰部闭环；缺了相对计算不敢用 | 进近期待办          |
| **建议做** | 明显增补，不挡主主张     | 可排期，落后必做一档     |
| **可后置** | 真有人要再做         | 不进近期待办，不对外承诺日期 |
| **不建议** | 明确不做 / 不承诺     | 仍写在需求里，避免被当成遗漏 |


不另设「不优先」。原「不优先」并入可后置或不建议。

## 已确认设计决策

- 覆盖对齐腰部常用比较方式，实现不对齐 Zabbix 函数目录；不引入触发器表达式语言。
- 百分位只放告警条件一个入口，不进现有窗口聚合下拉（avg/max/min/sum/count/last）。
- 十月百分位是评估窗内样本的 P90/P95/P99，不是直方图 `histogram_quantile`。真 bucket P95 单列可后置。
- 短环比对照是当前评估窗整体平移 1 小时 / 24 小时。界面写「1 小时前同窗 / 24 小时前同窗」，不写「昨天」。缺对照不误报。
- 试跑：未保存即可；复用扫描引擎；不落告警、不通知。结果含当前值、对照值、缺对照原因、本轮是否命中。连续 N 次才告时写明「本轮计一次命中，未达连续次数则现网不会建告警」。试跑评当前窗，不是历史回放。
- 滞回（建议做）最多一条独立恢复阈值，例如触发 >30%、恢复 <10%。不学 Zabbix 独立恢复表达式。未做滞回时，恢复线等于触发线，仍靠连续 N 次防抖。
- 公式保持现有四则，不强扩函数库、跨指标任意表达式或 Zabbix 风格 `count()`/`forecast()` 嵌套。
- 维护窗 / 静默 / 级别抑制归告警中心，不进监控策略计算表单。

## 附录：各计算方式说明

对照用，不是验收清单。Zabbix 函数名仅帮助懂 Zabbix 的人认场景，不表示要做同名函数。

### A. 保持



#### 固定阈值

当前评估值与一条静态线比较，如 CPU > 90%。Zabbix 里最常见的 `last()>90`。现网已有。保持。不在本覆盖里改比较符集合。

#### 窗口 avg / max / min / sum / count / last

先把评估窗收成一个数，再和阈值比。对应现网 `group_algorithm` + `avg_over_time` 等窗口算法。保持。新增百分位不塞进这一组下拉。

#### 无数据

评估窗内没有可用点则按无数据处理，用于采集掉线。现网已有。保持；检测窗 / 恢复窗拆表单属打磨，不挡必做。

#### 连续 N 次触发 / 恢复

条件要连续满足（或不满足）N 个扫描周期才建告警或恢复，防毛刺。现网 `recovery_condition` 及触发连续次数。保持。试跑必须说明：本轮命中 ≠ 现网已达连续次数。

#### 多级阈值

同一条件多档级别（如 Warning / Critical），级别只升不降直到恢复或关闭。现网已有。保持。

#### 公式四则

多指标用 `a / b * 100` 这类表达式得到最终结果再告警。现网已有且校验较严。保持，不强扩：不把 Zabbix 函数、跨对象查询、任意 PromQL 放进公式框。

### B. 必做



#### 百分位 P90 / P95 / P99

评估窗内样本的分位数再比线，看尾部而不是均值。典型：接口时延 P95 > 200ms。放在告警条件，与绝对值、变化量、短环比并列。

**不是**直方图 bucket 的 `histogram_quantile`。多数主机/插件指标是点值，本条按点值序列取分位。真直方图见「直方图分位」。

#### 变化量（上一窗）

当前评估窗的值减去（或相对）上一个等长窗口。例如 5 分钟窗，就是刚才 5 分钟对比再往前 5 分钟。看「比刚才多了/少了多少」，不是比 1 小时前。缺上一窗（新实例、断点）不误报。

#### 短环比（1h / 24h 同窗）

当前评估窗整体平移 1 小时或 24 小时，再比变化量或变化率。界面：「1 小时前同窗」「24 小时前同窗」。不是自然日「昨天 00:00–24:00」，也不绑组织时区。缺对照（未满 24h、对照窗无点）不误报，试跑写明跳过。更长同比见可后置。

#### 策略条件试跑

保存前用表单现值跑一遍扫描判定：选实例，看到当前值、对照值、缺对照原因、本轮是否命中；不落 Alert / Event / 快照 / 通知。现网预览只画序列和阈值线，不算试跑。评当前窗，不是「过去 24h 会告几次」。连续 N 次策略须区分本轮命中与现网会不会建单。权限跟策略 Operate。

### C. 建议做



#### 滞回

触发阈值和恢复阈值不是同一条线，避免在线附近来回翻。例如 CPU > 90% 告，< 80% 才恢复。现网恢复是「不再满足触发条件连续 N 次」，没有第二条线。

本档只做**一条恢复阈值**（可按级别各一条，若实现自然支持），不学 Zabbix 整段独立恢复表达式。未交付前，恢复线 = 触发线 + 连续 N 次。相对计算比固定阈值更容易抖，本档价值在环比/百分位上线之后。

#### 速率 rate

把单调计数器变成窗内速率（次/秒、字节/秒），再比线。部分插件查询已经是 `rate()`，策略层再包一层容易和窗口聚合重复。本档是策略条件上显式「按速率评估」，给原始计数器指标用。稍后于必做四条。

#### 条件计数（简化）

评估窗内「满足某条件的次数 ≥ N」则告，例如 5 分钟内失败次数 > 10。不同于连续 N 次（那是连续扫描周期）。Zabbix `count()` 能力更宽（匹配字符串、时间窗任意函数）。本档只做简化：对已算出的值做「窗内超阈点数 ≥ N」。现网连续 N 次可部分绕过防毛刺场景，故不进必做。

### D. 可后置



#### 同比更长

对照上月、去年或自然周。依赖更长留存和日历/时区。与短环比 24h 同窗不是一条需求。不对外承诺日期。

#### 容量预测

按近期斜率估计磁盘/inode「还有多久满」。Zabbix `forecast` / `timeleft` 一类。只能近似，假阳和单位（天/小时）都要产品化，不进近迭代。

#### 直方图分位

指标本身是 histogram bucket 时，用 `histogram_quantile` 得到真 P95。与必做「点值序列分位」分开。前置是采集侧有直方图。未具备前，延迟尾部用点值 P95，并在文档中写清差异。

#### 高阶统计

用标准差、分位距等判断「波动是否异常」，不是比一条固定线。易和统计基线、动态阈值混谈。有明确客户场景再做。

#### 统计基线

用多日或多季同时段的常态带宽包住当前值。比短环比重得多（训练窗、季节、时区）。可糙做，难做好。不进近迭代。

#### 长期趋势

看天/周是否持续上升或下降。Zabbix `trend*` 走趋势存储，不是原始点。现栈可近似，场景窄。可后置。

#### 单调增 / 减

期望一直涨（或一直跌）却停了，例如备份位点、队列积压本应下降。场景窄，可后置。

#### 变化次数

短窗内来回穿越阈值的次数过多，抓抖动而不是持续超线。与连续 N 次、条件计数都不同。场景窄，可后置。

### E. 不建议



#### 季节分解 STL（trendstl）

去掉季节项再判异常。Zabbix `trendstl` 一类。实现难、参数难解释、假阳难讲。明确不对齐、不承诺。售前若被问，答「不做季节分解异常检测；短环比覆盖比 1 小时前 / 24 小时前」。

#### Zabbix 函数全集

不把 `abschange`、`band`、`forecast`、`timeleft`、`trendstl` 等函数名做成表单或表达式表面。覆盖地图已按场景吸收腰部需要的比较方式；未列出的函数默认不建议，除非另开决策改档位。
